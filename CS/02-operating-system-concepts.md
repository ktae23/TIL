# 운영체제 개념

## 1. 프로세스 (Process)

### 프로세스란?

**프로세스**는 실행 중인 프로그램의 인스턴스입니다. 프로그램이 메모리에 적재되어 CPU를 할당받아 실행되면 프로세스가 됩니다.

### 프로세스의 메모리 구조

프로세스는 다음 4가지 영역으로 구성됩니다:

```
+------------------+  높은 주소
|      Stack       |  ← 지역변수, 함수 호출 정보
+------------------+
|        ↓         |
|                  |
|        ↑         |
+------------------+
|       Heap       |  ← 동적 할당 메모리
+------------------+
|       Data       |  ← 전역변수, 정적변수
+------------------+
|       Code       |  ← 실행 코드
+------------------+  낮은 주소
```

- **Code (Text)**: 실행할 프로그램의 코드가 저장되는 영역 (읽기 전용)
- **Data**: 전역 변수, 정적(static) 변수가 저장되는 영역
- **Heap**: 동적으로 할당되는 메모리 영역 (런타임에 크기 결정)
- **Stack**: 함수 호출 시 지역 변수, 매개변수, 리턴 주소가 저장되는 영역

### 프로세스 상태 (Process State)

```
            new
             │
             ▼
         ┌───────┐    admitted     ┌───────┐
         │ New   │───────────────▶│ Ready │◀──────┐
         └───────┘                 └───┬───┘      │
                                       │         │
                              scheduler│         │interrupt
                              dispatch │         │
                                       ▼         │
                                   ┌───────┐     │
                                   │Running│─────┘
                                   └───┬───┘
                                       │
                    ┌──────────────────┼──────────────────┐
                    │                  │                  │
               I/O or event       exit │            I/O or event
                  wait                 │              completion
                    ▼                  ▼                  │
               ┌─────────┐       ┌───────────┐           │
               │ Waiting │───────│Terminated │           │
               └─────────┴───────┴───────────┘───────────┘
```

- **New**: 프로세스가 생성 중인 상태
- **Ready**: CPU 할당을 기다리는 상태
- **Running**: CPU를 할당받아 실행 중인 상태
- **Waiting (Blocked)**: I/O 완료 등 이벤트를 기다리는 상태
- **Terminated**: 실행이 종료된 상태

### PCB (Process Control Block)

운영체제가 프로세스를 관리하기 위해 유지하는 자료구조입니다.

PCB에 포함되는 정보:
- **프로세스 ID (PID)**: 프로세스 고유 식별자
- **프로세스 상태**: Ready, Running, Waiting 등
- **프로그램 카운터 (PC)**: 다음 실행할 명령어 주소
- **CPU 레지스터**: 프로세스 실행 중 사용하던 레지스터 값들
- **메모리 관리 정보**: 페이지 테이블, 세그먼트 테이블 등
- **I/O 상태 정보**: 할당된 I/O 장치, 열린 파일 목록 등
- **계정 정보**: CPU 사용 시간, 시간 제한 등

### 컨텍스트 스위칭 (Context Switching)

CPU가 한 프로세스에서 다른 프로세스로 전환할 때 발생하는 과정입니다.

1. 현재 프로세스 상태를 PCB에 저장
2. 새로운 프로세스의 PCB에서 상태 복원
3. 새로운 프로세스 실행

컨텍스트 스위칭은 **순수한 오버헤드**입니다. 이 시간 동안 시스템은 유용한 작업을 수행하지 못합니다.

## 2. 쓰레드 (Thread)

### 쓰레드란?

**쓰레드**는 프로세스 내에서 실행되는 흐름의 단위입니다. 하나의 프로세스는 여러 개의 쓰레드를 가질 수 있습니다.

### 쓰레드의 특징

- **경량 프로세스 (Lightweight Process)** 라고도 불림
- 같은 프로세스 내의 쓰레드들은 Code, Data, Heap 영역을 공유
- 각 쓰레드는 고유한 Stack과 레지스터를 가짐

```
프로세스
┌─────────────────────────────────────────┐
│  Code  │  Data  │        Heap           │  ← 공유
├────────┴────────┴───────────────────────┤
│ Thread 1 │ Thread 2 │ Thread 3          │
│  Stack   │  Stack   │  Stack            │  ← 개별
│  PC      │  PC      │  PC               │
│ Register │ Register │ Register          │
└──────────┴──────────┴───────────────────┘
```

### 멀티쓰레딩의 장점

1. **응답성 (Responsiveness)**: 일부 쓰레드가 블록되어도 다른 쓰레드 실행 가능
2. **자원 공유 (Resource Sharing)**: 같은 프로세스 내 자원을 공유하여 효율적
3. **경제성 (Economy)**: 프로세스 생성보다 쓰레드 생성이 빠르고 컨텍스트 스위칭 비용 적음
4. **확장성 (Scalability)**: 멀티프로세서 환경에서 병렬 실행 가능

### 사용자 수준 쓰레드 vs 커널 수준 쓰레드

| 구분 | 사용자 수준 쓰레드 | 커널 수준 쓰레드 |
|------|-------------------|-----------------|
| 관리 주체 | 사용자 라이브러리 | 운영체제 커널 |
| 스케줄링 | 라이브러리에서 수행 | 커널에서 수행 |
| 컨텍스트 스위칭 | 빠름 (커널 개입 없음) | 느림 (커널 모드 전환 필요) |
| 블로킹 | 하나가 블록되면 전체 블록 | 개별 쓰레드만 블록 |
| 멀티프로세서 활용 | 불가 | 가능 |

## 3. 프로세스 vs 쓰레드

| 비교 항목 | 프로세스 | 쓰레드 |
|----------|---------|--------|
| 정의 | 실행 중인 프로그램 | 프로세스 내 실행 단위 |
| 메모리 | 독립적인 메모리 공간 | Code, Data, Heap 공유 |
| 통신 | IPC 필요 (파이프, 소켓 등) | 공유 메모리로 직접 통신 |
| 생성 비용 | 높음 | 낮음 |
| 컨텍스트 스위칭 | 비용 큼 | 비용 적음 |
| 안정성 | 하나가 죽어도 다른 프로세스 영향 없음 | 하나가 죽으면 전체 프로세스 영향 |
| 동기화 | 필요 없음 (독립적) | 필요 (공유 자원) |

### 언제 무엇을 사용할까?

**프로세스 사용**:
- 독립적인 실행이 필요한 경우
- 보안이 중요한 경우 (메모리 격리)
- 하나의 작업 실패가 다른 작업에 영향을 주면 안 되는 경우

**쓰레드 사용**:
- 같은 자원을 공유해야 하는 경우
- 빠른 컨텍스트 스위칭이 필요한 경우
- 멀티코어 환경에서 병렬 처리가 필요한 경우

## 4. CPU 스케줄링

### 스케줄링이란?

여러 프로세스가 CPU를 사용하려고 할 때, 어떤 프로세스에게 CPU를 할당할지 결정하는 것입니다.

### 스케줄링 기준

- **CPU 이용률 (CPU Utilization)**: CPU가 놀지 않고 일하는 비율
- **처리량 (Throughput)**: 단위 시간당 완료되는 프로세스 수
- **총 처리 시간 (Turnaround Time)**: 프로세스 제출부터 완료까지 시간
- **대기 시간 (Waiting Time)**: Ready 큐에서 대기한 총 시간
- **응답 시간 (Response Time)**: 요청 후 첫 응답까지 시간

### 스케줄링 알고리즘

#### FCFS (First-Come, First-Served)

먼저 도착한 프로세스를 먼저 처리합니다.

- **장점**: 구현이 간단
- **단점**: Convoy Effect 발생 가능 (긴 프로세스 뒤에 짧은 프로세스들이 대기)
- **비선점형**

#### SJF (Shortest Job First)

실행 시간이 가장 짧은 프로세스를 먼저 처리합니다.

- **장점**: 평균 대기 시간 최소화
- **단점**: 실행 시간 예측 어려움, 기아(Starvation) 문제
- **비선점형 / 선점형 (SRTF)**

#### Priority Scheduling

우선순위가 높은 프로세스를 먼저 처리합니다.

- **장점**: 중요한 작업 먼저 처리 가능
- **단점**: 기아(Starvation) 문제 → Aging으로 해결
- **선점형 / 비선점형**

#### Round Robin (RR)

각 프로세스에게 동일한 시간 할당량(Time Quantum)을 부여하고 순환 실행합니다.

- **장점**: 공정한 CPU 분배, 응답 시간 예측 가능
- **단점**: Time Quantum 크기에 따라 성능 차이
- **선점형**

```
Time Quantum = 4

Process    Burst Time
P1         24
P2         3
P3         3

실행 순서: P1(4) → P2(3) → P3(3) → P1(4) → P1(4) → P1(4) → P1(4) → P1(4)
```

#### Multilevel Queue

프로세스를 여러 그룹으로 나누어 각 그룹별로 다른 스케줄링 적용합니다.

#### Multilevel Feedback Queue

프로세스가 큐 사이를 이동할 수 있어 더 유연한 스케줄링이 가능합니다.

## 5. 프로세스 동기화

### 임계 구역 (Critical Section)

여러 프로세스가 공유하는 자원에 접근하는 코드 영역입니다.

### 임계 구역 문제 해결을 위한 3가지 조건

1. **상호 배제 (Mutual Exclusion)**: 한 프로세스가 임계 구역에 있으면 다른 프로세스는 진입 불가
2. **진행 (Progress)**: 임계 구역이 비어있으면 대기 중인 프로세스 중 하나가 진입 가능
3. **한정 대기 (Bounded Waiting)**: 대기 시간에 한계가 있어야 함 (기아 방지)

### 동기화 도구

#### Mutex (Mutual Exclusion)

```
acquire() {
    while (!available)
        ; // busy waiting
    available = false;
}

release() {
    available = true;
}
```

- 하나의 프로세스만 자원에 접근 가능
- Locking 메커니즘

#### Semaphore

```
wait(S) {  // P 연산
    while (S <= 0)
        ; // busy waiting
    S--;
}

signal(S) {  // V 연산
    S++;
}
```

- **Binary Semaphore**: 0 또는 1 (Mutex와 유사)
- **Counting Semaphore**: 여러 개의 자원 관리

#### Monitor

고급 동기화 도구로, 상호 배제를 자동으로 보장합니다.

```java
monitor BoundedBuffer {
    private items[];
    private count = 0;

    condition notFull, notEmpty;

    public void insert(item) {
        if (count == N) wait(notFull);
        items[count++] = item;
        signal(notEmpty);
    }

    public item remove() {
        if (count == 0) wait(notEmpty);
        item = items[--count];
        signal(notFull);
        return item;
    }
}
```

## 6. 교착상태 (Deadlock)

### 교착상태란?

두 개 이상의 프로세스가 서로 상대방의 자원을 기다리며 무한히 대기하는 상태입니다.

```
프로세스 A                     프로세스 B
    │                             │
    │  자원 1 보유                 │  자원 2 보유
    │                             │
    ▼                             ▼
자원 2 요청 ─────────────────── 자원 1 요청
    │         (교착상태!)          │
    └─────────────────────────────┘
```

### 교착상태 발생 조건 (4가지 모두 충족 시 발생)

1. **상호 배제 (Mutual Exclusion)**: 자원은 한 번에 한 프로세스만 사용 가능
2. **점유와 대기 (Hold and Wait)**: 자원을 보유한 채 다른 자원을 기다림
3. **비선점 (No Preemption)**: 자원을 강제로 빼앗을 수 없음
4. **순환 대기 (Circular Wait)**: 프로세스들이 순환적으로 서로의 자원을 대기

### 교착상태 처리 방법

#### 1. 예방 (Prevention)

4가지 조건 중 하나를 사전에 부정합니다.

- 상호 배제 부정: 공유 가능한 자원으로 변경 (현실적으로 어려움)
- 점유와 대기 부정: 모든 자원을 한 번에 요청
- 비선점 부정: 자원 선점 허용
- 순환 대기 부정: 자원에 순서를 부여하여 순서대로만 요청

#### 2. 회피 (Avoidance)

시스템이 안전 상태를 유지하도록 자원 할당을 결정합니다.

**은행원 알고리즘 (Banker's Algorithm)**:
- 각 프로세스의 최대 자원 요구량을 미리 파악
- 자원 할당 시 안전 상태 유지 여부 확인
- 안전하지 않으면 자원 할당 거부

#### 3. 탐지 및 복구 (Detection and Recovery)

교착상태 발생을 허용하되, 탐지 후 복구합니다.

- **탐지**: 자원 할당 그래프로 사이클 탐지
- **복구**:
  - 프로세스 종료 (전체 또는 하나씩)
  - 자원 선점 (희생자 선택, 롤백)

#### 4. 무시 (Ignorance)

교착상태가 드물게 발생한다고 가정하고 무시합니다. (타조 알고리즘)

## 7. 메모리 관리

### 주소 바인딩

프로그램의 논리 주소를 물리 주소로 변환하는 과정입니다.

- **컴파일 시간 바인딩**: 컴파일 시 물리 주소 결정 (위치 고정)
- **로드 시간 바인딩**: 프로그램 로드 시 물리 주소 결정
- **실행 시간 바인딩**: 실행 중에 물리 주소 결정 (MMU 필요)

### 연속 메모리 할당

프로세스를 메모리의 연속된 공간에 할당합니다.

**할당 전략**:
- **First Fit**: 첫 번째로 충분한 공간에 할당 (빠름)
- **Best Fit**: 가장 적합한 크기의 공간에 할당 (외부 단편화 최소화)
- **Worst Fit**: 가장 큰 공간에 할당 (큰 빈 공간 유지)

### 단편화 (Fragmentation)

- **외부 단편화**: 메모리 공간이 여러 조각으로 나뉘어 사용 불가
- **내부 단편화**: 할당된 공간 중 사용되지 않는 부분

### 페이징 (Paging)

물리 메모리를 동일한 크기의 **프레임**으로, 논리 메모리를 동일한 크기의 **페이지**로 나눕니다.

```
논리 주소                    물리 주소
┌────────┬────────┐         ┌────────┐
│ 페이지  │ 오프셋  │    ──▶  │프레임+오프셋│
│ 번호   │        │         └────────┘
└────────┴────────┘
         │
         ▼
    ┌─────────────┐
    │ 페이지 테이블 │
    └─────────────┘
```

**장점**: 외부 단편화 없음
**단점**: 내부 단편화 발생 가능, 페이지 테이블 메모리 필요

### 세그먼테이션 (Segmentation)

프로그램을 의미 있는 단위(코드, 데이터, 스택 등)로 나눕니다.

```
논리 주소
┌─────────────┬────────┐
│ 세그먼트 번호 │ 오프셋  │
└─────────────┴────────┘
         │
         ▼
    ┌──────────────────┐
    │ 세그먼트 테이블    │
    │ (base, limit)    │
    └──────────────────┘
```

**장점**: 논리적 단위로 관리, 공유/보호 용이
**단점**: 외부 단편화 발생

---

## 8. 가상 메모리

### 가상 메모리란?

실제 물리 메모리보다 큰 메모리 공간을 사용할 수 있게 해주는 기법입니다. 프로그램 전체가 메모리에 있을 필요 없이, 필요한 부분만 메모리에 적재합니다.

### 요구 페이징 (Demand Paging)

페이지가 필요할 때만 메모리에 적재합니다.

```
┌────────────────────────────────────────┐
│           논리 주소 공간                │
├─────┬─────┬─────┬─────┬─────┬─────┬────┤
│ P0  │ P1  │ P2  │ P3  │ P4  │ P5  │... │
│ V   │ V   │ I   │ V   │ I   │ I   │    │
└──┬──┴──┬──┴──┬──┴──┬──┴─────┴─────┴────┘
   │     │     │     │
   │     │     │     └──────────┐
   │     │     │                │
   │     │     └─ Page Fault    │
   │     │                      │
   ▼     ▼                      ▼
┌─────┬─────┬─────┬─────┐   ┌────────┐
│ F0  │ F1  │ F2  │ F3  │   │  Disk  │
└─────┴─────┴─────┴─────┘   └────────┘
      물리 메모리

V = Valid (메모리에 있음)
I = Invalid (디스크에 있음)
```

### 페이지 폴트 (Page Fault)

접근하려는 페이지가 메모리에 없을 때 발생합니다.

**처리 과정**:
1. 페이지 테이블 참조 → Invalid 확인
2. 트랩 발생 (운영체제로 제어 이동)
3. 디스크에서 해당 페이지 찾기
4. 빈 프레임 찾기 (없으면 페이지 교체)
5. 디스크에서 메모리로 페이지 적재
6. 페이지 테이블 업데이트
7. 중단된 명령어 재실행

### 페이지 교체 알고리즘

메모리가 가득 찼을 때 어떤 페이지를 내보낼지 결정합니다.

#### FIFO (First-In First-Out)

가장 먼저 들어온 페이지를 교체합니다.

- **장점**: 구현 간단
- **단점**: Belady's Anomaly 발생 가능 (프레임 늘어도 페이지 폴트 증가)

#### Optimal (OPT)

앞으로 가장 오랫동안 사용되지 않을 페이지를 교체합니다.

- **장점**: 최적의 성능
- **단점**: 미래 예측 불가 (비현실적)

#### LRU (Least Recently Used)

가장 오랫동안 사용되지 않은 페이지를 교체합니다.

- **장점**: OPT에 근접한 성능
- **단점**: 구현 복잡 (시간 기록 필요)

```
참조 문자열: 7, 0, 1, 2, 0, 3, 0, 4, 2, 3, 0, 3, 2, 1, 2
프레임 수: 3

LRU 동작:
7 → [7, -, -]     Page Fault
0 → [7, 0, -]     Page Fault
1 → [7, 0, 1]     Page Fault
2 → [2, 0, 1]     Page Fault (7 교체)
0 → [2, 0, 1]     Hit
3 → [2, 0, 3]     Page Fault (1 교체)
...
```

#### LFU (Least Frequently Used)

참조 횟수가 가장 적은 페이지를 교체합니다.

#### Clock Algorithm (Second Chance)

FIFO의 변형으로, 참조 비트를 사용하여 두 번째 기회를 줍니다.

### 스래싱 (Thrashing)

페이지 폴트가 과도하게 발생하여 프로세스가 실제 작업보다 페이지 교체에 더 많은 시간을 소비하는 현상입니다.

**원인**: 멀티프로그래밍 정도가 과도하게 높아 각 프로세스에 할당된 프레임 부족

**해결 방법**:
- Working Set Model: 각 프로세스의 워킹셋 크기만큼 프레임 할당
- Page Fault Frequency: 페이지 폴트 빈도로 프레임 조절

## 9. 파일 시스템

### 파일 시스템이란?

파일과 디렉토리를 관리하고, 보조기억장치의 공간을 효율적으로 사용하기 위한 시스템입니다.

### 파일 할당 방법

#### 연속 할당 (Contiguous Allocation)

파일을 연속된 블록에 저장합니다.

- **장점**: 순차/직접 접근 빠름
- **단점**: 외부 단편화, 파일 크기 증가 어려움

#### 연결 할당 (Linked Allocation)

각 블록에 다음 블록의 포인터를 저장합니다.

- **장점**: 외부 단편화 없음, 파일 크기 증가 용이
- **단점**: 직접 접근 불가, 포인터 저장 공간 필요

#### 색인 할당 (Indexed Allocation)

인덱스 블록에 모든 포인터를 저장합니다.

- **장점**: 직접 접근 가능, 외부 단편화 없음
- **단점**: 인덱스 블록 오버헤드

### 디렉토리 구조

- **단일 레벨**: 모든 파일이 하나의 디렉토리에
- **2레벨**: 사용자별 디렉토리
- **트리 구조**: 계층적 디렉토리 (현재 대부분 사용)
- **비순환 그래프**: 파일 공유 지원 (링크)

### 파일 시스템 예시

- **FAT**: 파일 할당 테이블 사용 (USB, SD 카드)
- **NTFS**: Windows 파일 시스템
- **ext4**: Linux 파일 시스템
- **APFS**: macOS 파일 시스템
