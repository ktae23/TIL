# 복식부기의 원리 (Double-Entry Bookkeeping)

> 📚 **선수 지식**: [회계란 무엇인가](./01-accounting-basics.md)

## 개요

복식부기 (Double-Entry Bookkeeping)는 모든 거래를 **차변 (Debit)**과 **대변 (Credit)** 양쪽에 동시에 기록하는 부기 방법이다. 하나의 거래가 발생하면 반드시 두 개 이상의 계정에 영향을 미치며, 차변의 합계와 대변의 합계는 항상 일치해야 한다. 이것이 복식부기의 핵심 원리인 **대차평균의 원리 (Trial Balance Principle)** 이다.

1494년 이탈리아의 수학자 루카 파치올리 (Luca Pacioli)가 체계적으로 정리한 이래, 복식부기는 500년 이상 전 세계 회계의 기본 원리로 사용되고 있다.

---

## 단식부기 vs 복식부기 비교

### 단식부기 (Single-Entry Bookkeeping)

단식부기는 현금의 입출금만을 기록하는 간단한 방법이다. 가계부와 유사하다.

**예시: 상품 100만 원을 현금으로 판매한 경우**

```
날짜: 2026-01-15
내용: 상품 판매
입금: 1,000,000원
```

**장점**:
- 간단하고 이해하기 쉽다
- 소규모 사업자에게 적합하다

**단점**:
- 자산, 부채의 전체 현황을 파악할 수 없다
- 재무제표 (Financial Statements) 작성이 불가능하다
- 거래의 원인과 결과를 파악하기 어렵다
- 오류 검증이 어렵다

### 복식부기 (Double-Entry Bookkeeping)

복식부기는 모든 거래를 차변과 대변에 동시에 기록한다.

**예시: 상품 100만 원을 현금으로 판매한 경우**

```
날짜: 2026-01-15
차변 (Debit) : 현금 (Cash)       1,000,000원
대변 (Credit): 매출 (Sales)      1,000,000원
```

현금이 들어온 것 (자산 증가)과 매출이 발생한 것 (수익 증가)을 동시에 기록한다.

**장점**:
- 자산, 부채, 자본의 전체 현황을 정확히 파악할 수 있다
- 재무제표 작성이 가능하다
- 거래의 원인과 결과를 동시에 기록하여 추적이 용이하다
- 대차평균의 원리로 오류를 자동 검증할 수 있다
- 법적 요구사항을 충족한다

### 비교 요약

| 구분 | 단식부기 (Single-Entry) | 복식부기 (Double-Entry) |
|------|----------------------|----------------------|
| 기록 방식 | 한쪽만 기록 | 차변/대변 양쪽 기록 |
| 오류 검증 | 어려움 | 대차평균으로 자동 검증 |
| 재무제표 | 작성 불가 | 작성 가능 |
| 재산 파악 | 현금만 파악 | 전체 자산/부채/자본 파악 |
| 법적 요건 | 간편장부 (Simplified Bookkeeping) | 정규장부 (Formal Bookkeeping) |
| 적용 대상 | 소규모 개인사업자 | 법인, 일정 규모 이상 개인사업자 |

> **세무기장 실무 포인트**: 한국 세법상 직전 과세기간 수입금액이 일정 기준 이상인 사업자는 복식부기 의무자 (Double-Entry Bookkeeping Obligor)로서 복식부기로 장부를 작성해야 한다. 기준 미만 사업자는 간편장부 (Simplified Bookkeeping)를 사용할 수 있다.

## 차변 (Debit)과 대변 (Credit) 개념

### 기본 개념

- **차변 (Debit, Dr.)**: 분개에서 왼쪽에 기록하는 항목
- **대변 (Credit, Cr.)**: 분개에서 오른쪽에 기록하는 항목

> **주의**: 차변과 대변은 "좋다/나쁘다" 또는 "들어오다/나가다"의 의미가 아니다. 단순히 기록 위치 (왼쪽/오른쪽)를 나타내는 용어이다.

### 계정 유형별 차변/대변 증감 규칙

각 계정의 유형에 따라 증가와 감소를 기록하는 위치가 다르다.

| 계정 유형 | 증가 시 기록 위치 | 감소 시 기록 위치 |
|----------|----------------|----------------|
| 자산 (Assets) | 차변 (Debit) | 대변 (Credit) |
| 부채 (Liabilities) | 대변 (Credit) | 차변 (Debit) |
| 자본 (Equity) | 대변 (Credit) | 차변 (Debit) |
| 수익 (Revenue) | 대변 (Credit) | 차변 (Debit) |
| 비용 (Expenses) | 차변 (Debit) | 대변 (Credit) |

이 규칙을 외우는 방법:

```
회계 등식: 자산 = 부채 + 자본
             │        │
        차변 증가   대변 증가

수익은 자본을 증가시키므로 → 대변 증가
비용은 자본을 감소시키므로 → 차변 증가
```

### 정상잔액 (Normal Balance)

각 계정 유형의 정상잔액은 해당 계정이 증가하는 방향과 같다.

| 계정 유형 | 정상잔액 |
|----------|---------|
| 자산 (Assets) | 차변잔액 (Debit Balance) |
| 부채 (Liabilities) | 대변잔액 (Credit Balance) |
| 자본 (Equity) | 대변잔액 (Credit Balance) |
| 수익 (Revenue) | 대변잔액 (Credit Balance) |
| 비용 (Expenses) | 차변잔액 (Debit Balance) |

## 거래의 이중성 (Duality of Transactions)

### 개념

모든 경제적 거래는 반드시 **두 가지 이상의 측면**을 가진다. 하나의 거래가 발생하면 최소 두 개의 계정에 영향을 미치며, 한쪽이 증가하면 다른 한쪽도 반드시 변동한다.

이것을 **거래의 이중성 (Duality of Transactions)** 또는 **거래의 8요소**라고 한다.

### 거래의 8요소

모든 거래는 다음 8가지 요소의 조합으로 설명된다:

| 차변 요소 (Debit Elements) | 대변 요소 (Credit Elements) |
|--------------------------|--------------------------|
| 자산의 증가 (Asset ↑) | 자산의 감소 (Asset ↓) |
| 부채의 감소 (Liability ↓) | 부채의 증가 (Liability ↑) |
| 자본의 감소 (Equity ↓) | 자본의 증가 (Equity ↑) |
| 비용의 발생 (Expense ↑) | 수익의 발생 (Revenue ↑) |

### 거래의 결합 관계

거래의 8요소가 실제로 결합되는 패턴은 다음과 같다:

**1) 자산 증가 & 자산 감소 (교환 거래)**
```
예: 현금 500만 원으로 비품 구입
차변: 비품 (Equipment)   5,000,000원  → 자산 증가
대변: 현금 (Cash)        5,000,000원  → 자산 감소
```

**2) 자산 증가 & 부채 증가**
```
예: 은행에서 1,000만 원 차입
차변: 현금 (Cash)           10,000,000원  → 자산 증가
대변: 차입금 (Borrowings)    10,000,000원  → 부채 증가
```

**3) 자산 증가 & 자본 증가**
```
예: 주주가 현금 5,000만 원 출자
차변: 현금 (Cash)         50,000,000원  → 자산 증가
대변: 자본금 (Capital)    50,000,000원  → 자본 증가
```

**4) 자산 증가 & 수익 발생**
```
예: 상품을 현금 200만 원에 판매
차변: 현금 (Cash)         2,000,000원  → 자산 증가
대변: 매출 (Sales)        2,000,000원  → 수익 발생
```

**5) 비용 발생 & 자산 감소**
```
예: 사무실 임차료 100만 원 현금 지급
차변: 임차료 (Rent Expense)  1,000,000원  → 비용 발생
대변: 현금 (Cash)            1,000,000원  → 자산 감소
```

**6) 부채 감소 & 자산 감소**
```
예: 차입금 500만 원 현금 상환
차변: 차입금 (Borrowings)  5,000,000원  → 부채 감소
대변: 현금 (Cash)          5,000,000원  → 자산 감소
```

## 대차평균의 원리 (Trial Balance Principle)

### 개념

복식부기에서 모든 거래의 **차변 합계와 대변 합계는 항상 일치**해야 한다. 이를 대차평균의 원리라고 한다.

```
모든 차변 금액의 합계 = 모든 대변 금액의 합계
```

이 원리에 의해:
- 개별 분개의 차변 합계 = 대변 합계
- 총계정원장 (General Ledger) 전체의 차변잔액 합계 = 대변잔액 합계
- 시산표 (Trial Balance)의 차변 합계 = 대변 합계

### 시산표 (Trial Balance)

시산표는 일정 시점에서 모든 계정의 잔액을 모아 대차평균의 원리가 성립하는지 검증하는 표이다.

**시산표 예시**:

| 계정과목 | 차변잔액 (Dr.) | 대변잔액 (Cr.) |
|---------|--------------|--------------|
| 현금 (Cash) | 15,000,000 | |
| 매출채권 (Accounts Receivable) | 5,000,000 | |
| 비품 (Equipment) | 10,000,000 | |
| 매입채무 (Accounts Payable) | | 3,000,000 |
| 차입금 (Borrowings) | | 7,000,000 |
| 자본금 (Capital) | | 10,000,000 |
| 매출 (Sales) | | 20,000,000 |
| 급여 (Salary Expense) | 8,000,000 | |
| 임차료 (Rent Expense) | 2,000,000 | |
| **합계** | **40,000,000** | **40,000,000** |

차변 합계와 대변 합계가 일치하므로 기록이 올바르게 되었음을 확인할 수 있다.

### 대차가 불일치하는 경우

시산표의 차변 합계와 대변 합계가 일치하지 않으면 다음과 같은 오류가 있을 수 있다:

1. **기록 누락 (Omission)**: 거래의 한쪽만 기록한 경우
2. **금액 오류 (Amount Error)**: 차변과 대변의 금액을 다르게 기록한 경우
3. **전기 오류 (Posting Error)**: 원장에 전기할 때 금액을 잘못 옮긴 경우
4. **차변/대변 혼동 (Debit/Credit Confusion)**: 차변에 기록해야 할 것을 대변에 기록한 경우

> **참고**: 대차가 일치하더라도 모든 기록이 정확하다고는 할 수 없다. 예를 들어, 거래를 아예 기록하지 않았거나 (누락의 오류), 잘못된 계정에 기록한 경우 (계정 오류)에는 대차가 일치하면서도 오류가 존재할 수 있다.

## 구체적인 거래 예시

복식부기의 이해를 돕기 위해 창업부터 영업까지의 거래를 순서대로 살펴보자.

### 예시 1: 회사 설립 — 현금 출자

사장이 현금 5,000만 원을 출자하여 회사를 설립했다.

```
차변: 현금 (Cash)         50,000,000원
대변: 자본금 (Capital)    50,000,000원
```
- 현금 (자산)이 증가했으므로 차변
- 자본금 (자본)이 증가했으므로 대변

### 예시 2: 사무실 보증금 지급

사무실 임대 보증금 1,000만 원을 현금으로 지급했다.

```
차변: 임차보증금 (Lease Deposit)  10,000,000원
대변: 현금 (Cash)                 10,000,000원
```
- 임차보증금 (자산)이 증가했으므로 차변
- 현금 (자산)이 감소했으므로 대변

### 예시 3: 은행 대출

운영 자금 2,000만 원을 은행에서 대출받았다.

```
차변: 보통예금 (Bank Deposit)    20,000,000원
대변: 장기차입금 (Long-term Borrowings) 20,000,000원
```
- 보통예금 (자산)이 증가했으므로 차변
- 장기차입금 (부채)이 증가했으므로 대변

### 예시 4: 비품 외상 구입

컴퓨터와 사무용 가구를 500만 원에 외상으로 구입했다.

```
차변: 비품 (Equipment)          5,000,000원
대변: 미지급금 (Accounts Payable) 5,000,000원
```
- 비품 (자산)이 증가했으므로 차변
- 미지급금 (부채)이 증가했으므로 대변

### 예시 5: 상품 매입 (현금)

판매할 상품을 현금 300만 원에 매입했다.

```
차변: 상품 (Merchandise)   3,000,000원
대변: 현금 (Cash)          3,000,000원
```
- 상품 (자산)이 증가했으므로 차변
- 현금 (자산)이 감소했으므로 대변

### 예시 6: 상품 판매 (외상)

상품을 800만 원에 외상으로 판매했다.

```
차변: 매출채권 (Accounts Receivable)  8,000,000원
대변: 매출 (Sales Revenue)            8,000,000원
```
- 매출채권 (자산)이 증가했으므로 차변
- 매출 (수익)이 발생했으므로 대변

### 예시 7: 급여 지급

직원 급여 400만 원을 보통예금에서 이체했다.

```
차변: 급여 (Salary Expense)     4,000,000원
대변: 보통예금 (Bank Deposit)   4,000,000원
```
- 급여 (비용)이 발생했으므로 차변
- 보통예금 (자산)이 감소했으므로 대변

### 예시 8: 외상 대금 회수

예시 6에서 발생한 매출채권 중 500만 원을 현금으로 회수했다.

```
차변: 현금 (Cash)                    5,000,000원
대변: 매출채권 (Accounts Receivable)  5,000,000원
```
- 현금 (자산)이 증가했으므로 차변
- 매출채권 (자산)이 감소했으므로 대변

## 복식부기의 흐름 요약

```
거래 발생
    │
    ▼
분개 (Journal Entry) ──── 차변/대변 기록
    │
    ▼
전기 (Posting) ──── 총계정원장에 옮겨 기록
    │
    ▼
시산표 (Trial Balance) ──── 대차평균 검증
    │
    ▼
재무제표 (Financial Statements) 작성
```

### 개발자가 알아야 할 것 (What Developers Need to Know)

#### 시스템 설계에 미치는 영향

- **차변/대변 균형 강제 (Balance Enforcement)**: 분개 저장 시 차변 합계와 대변 합계가 일치하는지 반드시 검증하는 로직이 필요하다. 불일치 시 저장을 거부해야 한다.
- **원장 잔액 계산**: 계정별 잔액은 차변 합계에서 대변 합계를 빼거나 (자산/비용 계정), 대변 합계에서 차변 합계를 빼서 (부채/자본/수익 계정) 계산한다. 정상잔액 방향을 메타데이터로 관리해야 한다.
- **거래 원자성 (Transaction Atomicity)**: 하나의 분개에 포함된 모든 행 (차변/대변)은 하나의 DB 트랜잭션으로 처리되어야 한다. 부분 저장은 대차 불균형을 초래한다.

#### 데이터 모델링 포인트

```sql
-- 분개 헤더 (Journal Entry Header)
CREATE TABLE journal_entry (
    id          BIGINT PRIMARY KEY,
    entry_date  DATE NOT NULL,         -- 거래일자
    description VARCHAR(500),           -- 적요
    created_at  TIMESTAMP DEFAULT NOW(),
    created_by  VARCHAR(100)
);

-- 분개 상세 (Journal Entry Line)
CREATE TABLE journal_entry_line (
    id              BIGINT PRIMARY KEY,
    journal_entry_id BIGINT REFERENCES journal_entry(id),
    account_code    VARCHAR(10) NOT NULL,  -- 계정과목 코드
    debit_amount    BIGINT DEFAULT 0,      -- 차변 금액 (원 단위 정수)
    credit_amount   BIGINT DEFAULT 0,      -- 대변 금액 (원 단위 정수)
    CHECK (debit_amount >= 0 AND credit_amount >= 0),
    CHECK (debit_amount = 0 OR credit_amount = 0)  -- 한 행에 차변 또는 대변 하나만
);
```

- 금액은 **원 단위 정수 (BIGINT)** 로 저장하여 부동소수점 오류를 방지한다.
- 하나의 행에는 차변 또는 대변 중 하나만 기록하는 것이 일반적이다.
- 분개 저장 시 `SUM(debit_amount) = SUM(credit_amount)` 검증이 필수이다.

#### ERP/회계 프로그램 연동 시 참고 사항

- 대부분의 회계 소프트웨어는 분개 입력 시 자동으로 대차 균형을 검증한다. API 연동 시에도 이 검증 로직을 반드시 구현해야 한다.
- **자동 분개 (Auto Journal Entry)** 기능 구현 시, 거래 유형별로 미리 정의된 분개 템플릿을 활용하면 효율적이다.
- 기간 마감 (Period Close) 후에는 해당 기간의 분개를 수정할 수 없도록 잠금 (Lock) 기능이 필요하다.
- 수정이 필요한 경우 원래 분개를 역분개 (Reversing Entry)하고 새로운 분개를 작성하는 방식으로 처리한다.

### 용어 사전 (Glossary)

| 한글 | 영문 | 설명 |
|------|------|------|
| 복식부기 | Double-Entry Bookkeeping | 모든 거래를 차변과 대변 양쪽에 기록하는 부기 방법 |
| 단식부기 | Single-Entry Bookkeeping | 현금 입출금만 기록하는 간단한 부기 방법 |
| 차변 | Debit (Dr.) | 분개에서 왼쪽에 기록하는 항목 |
| 대변 | Credit (Cr.) | 분개에서 오른쪽에 기록하는 항목 |
| 거래의 이중성 | Duality of Transactions | 모든 거래가 두 가지 이상의 측면을 가지는 성질 |
| 대차평균의 원리 | Trial Balance Principle | 차변 합계와 대변 합계가 항상 일치하는 원리 |
| 시산표 | Trial Balance | 모든 계정 잔액을 모아 대차균형을 검증하는 표 |
| 정상잔액 | Normal Balance | 각 계정 유형의 기본적인 잔액 방향 (차변 또는 대변) |
| 간편장부 | Simplified Bookkeeping | 소규모 사업자가 사용하는 단식부기 방식의 간편한 장부 |
| 복식부기 의무자 | Double-Entry Bookkeeping Obligor | 세법상 복식부기로 장부를 작성해야 하는 사업자 |
| 역분개 | Reversing Entry | 기존 분개를 취소하기 위해 차변과 대변을 반대로 기록하는 분개 |
| 원자성 | Atomicity | DB 트랜잭션이 전부 성공하거나 전부 실패해야 하는 성질 |
| 분개 템플릿 | Journal Entry Template | 자주 발생하는 거래 유형에 대해 미리 정의된 분개 형식 |
