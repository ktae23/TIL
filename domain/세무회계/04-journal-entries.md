# 분개와 전기 (Journal Entries and Posting)

> 📚 **선수 지식**: [복식부기의 원리](./02-double-entry-bookkeeping.md), [계정과목 이해하기](./03-chart-of-accounts.md)

## 개요

분개 (Journal Entry)는 경제적 거래가 발생했을 때, 이를 차변 (Debit)과 대변 (Credit)으로 나누어 분개장 (Journal)에 기록하는 과정이다. 전기 (Posting)는 분개장에 기록된 내용을 총계정원장 (General Ledger)의 각 계정별로 옮겨 기록하는 과정이다.

분개와 전기는 회계 순환과정 (Accounting Cycle)의 핵심 단계이며, 모든 재무제표 (Financial Statements)는 이 과정에서 기록된 데이터를 기반으로 작성된다.

```
거래 발생 → 분개 (Journal Entry) → 전기 (Posting) → 시산표 (Trial Balance) → 재무제표
```

## 분개장 (Journal) 작성법

### 분개장이란

분개장은 거래가 발생한 순서대로 (연대순, Chronological Order) 분개를 기록하는 장부이다. "회계의 일기장"이라고 생각하면 쉽다.

### 분개의 구성 요소

하나의 분개에는 다음 요소가 포함된다:

| 구성 요소 | 영문 | 설명 |
|----------|------|------|
| 거래일자 | Date | 거래가 발생한 날짜 |
| 계정과목 | Account | 차변과 대변에 해당하는 계정과목 |
| 차변 금액 | Debit Amount | 차변에 기록할 금액 |
| 대변 금액 | Credit Amount | 대변에 기록할 금액 |
| 적요 | Description / Narration | 거래의 내용을 간략히 설명 |

### 분개 작성 순서

**1단계**: 거래 내용을 파악한다.
**2단계**: 관련 계정과목을 결정한다.
**3단계**: 각 계정의 증감을 판단한다.
**4단계**: 차변과 대변을 결정한다.
**5단계**: 금액을 기록하고 적요를 작성한다.

### 분개 작성 형식

```
날짜: YYYY-MM-DD
(차변) 계정과목명     금액
(대변)   계정과목명         금액
적요: 거래 설명
```

관례적으로:
- 차변 계정은 왼쪽 정렬
- 대변 계정은 들여쓰기 (Indent)하여 표기
- 차변을 먼저, 대변을 나중에 기록

### 분개장 양식 예시

| 날짜 | 적요 | 계정과목 | 차변 (Dr.) | 대변 (Cr.) |
|------|------|---------|-----------|-----------|
| 2026-01-02 | 현금 출자로 회사 설립 | 현금 (Cash) | 50,000,000 | |
| | | 자본금 (Capital) | | 50,000,000 |
| 2026-01-05 | 사무실 보증금 지급 | 임차보증금 (Lease Deposit) | 10,000,000 | |
| | | 현금 (Cash) | | 10,000,000 |

## 단순분개와 복합분개

### 단순분개 (Simple Journal Entry)

하나의 차변 계정과 하나의 대변 계정으로 구성되는 분개이다.

```
2026-01-10
(차변) 현금 (Cash)              5,000,000
(대변)   매출 (Sales Revenue)           5,000,000
적요: 상품 현금 판매
```

### 복합분개 (Compound Journal Entry)

둘 이상의 차변 계정이나 대변 계정이 포함되는 분개이다.

```
2026-01-15
(차변) 현금 (Cash)              3,000,000
(차변) 매출채권 (A/R)           2,000,000
(대변)   매출 (Sales Revenue)           5,000,000
적요: 상품 판매 (현금 300만, 외상 200만)
```

```
2026-01-20
(차변) 급여 (Salary Expense)    4,000,000
(대변)   예수금 (Withholdings)            400,000
(대변)   보통예금 (Bank Deposit)        3,600,000
적요: 1월분 급여 지급 (소득세 원천징수)
```

> **핵심 원칙**: 단순분개든 복합분개든 **차변 합계 = 대변 합계**는 반드시 성립해야 한다.

## 총계정원장 (General Ledger) 전기

### 총계정원장이란

총계정원장 (General Ledger, GL)은 **계정과목별로** 모든 거래를 정리한 장부이다. 분개장이 시간순으로 기록하는 것이라면, 총계정원장은 계정별로 모아서 기록하는 것이다.

### 전기 (Posting)의 개념

전기란 분개장에 기록된 각 항목을 해당하는 계정과목의 원장 계정에 옮겨 적는 과정이다.

```
분개장 (Journal)                  총계정원장 (General Ledger)
┌──────────────────┐              ┌─────────────────┐
│ 01/02             │              │   현금 계정       │
│ 현금    50,000,000│  ──전기──▶  │ 01/02 50,000,000 │
│  자본금 50,000,000│              │ 01/05 10,000,000 │
│                  │              └─────────────────┘
│ 01/05             │              ┌─────────────────┐
│ 임차보증금        │              │   자본금 계정     │
│       10,000,000 │  ──전기──▶  │ 01/02 50,000,000 │
│  현금  10,000,000│              └─────────────────┘
└──────────────────┘              ┌─────────────────┐
                                  │  임차보증금 계정  │
                                  │ 01/05 10,000,000 │
                                  └─────────────────┘
```

### 전기 절차

1. 분개장에서 차변 항목의 계정을 찾아 원장의 해당 계정 차변에 금액을 기록한다.
2. 분개장에서 대변 항목의 계정을 찾아 원장의 해당 계정 대변에 금액을 기록한다.
3. 분개장과 원장에 상호 참조 (Cross-Reference) 번호를 기입하여 추적을 가능하게 한다.

### 원장 양식 예시

**현금 (Cash) 계정 원장**:

| 날짜 | 적요 | 차변 (Dr.) | 대변 (Cr.) | 잔액 |
|------|------|-----------|-----------|------|
| 01/02 | 현금 출자 | 50,000,000 | | 50,000,000 |
| 01/05 | 사무실 보증금 지급 | | 10,000,000 | 40,000,000 |
| 01/10 | 상품 현금 판매 | 5,000,000 | | 45,000,000 |
| 01/15 | 상품 현금 판매 (일부) | 3,000,000 | | 48,000,000 |
| 01/20 | 급여 지급 | | 3,600,000 | 44,400,000 |

## T계정 (T-Account)

### T계정이란

T계정은 총계정원장을 간략하게 표현한 **학습용 도구**이다. 알파벳 "T" 모양으로, 왼쪽에 차변, 오른쪽에 대변을 기록한다.

### T계정 형식

```
        계정과목명
   ──────────────────
   차변 (Dr.) │ 대변 (Cr.)
   ──────────┼──────────
             │
             │
   ──────────┼──────────
   차변 합계  │ 대변 합계
```

### T계정 예시

아래 거래들을 T계정으로 표현해보자:

1. 현금 5,000만 원 출자
2. 보증금 1,000만 원 현금 지급
3. 상품 300만 원 현금 매입
4. 상품 800만 원 외상 판매
5. 급여 400만 원 현금 지급

```
          현금 (Cash)                      자본금 (Capital)
   ──────────────────────          ──────────────────────
   (1) 50,000,000 │ (2) 10,000,000     │ (1) 50,000,000
                  │ (3)  3,000,000     │
                  │ (5)  4,000,000     │
   ──────────────┼──────────      ────┼──────────────
   50,000,000    │ 17,000,000         │ 50,000,000
   잔액: 33,000,000 (차변)        잔액: 50,000,000 (대변)


       임차보증금 (Lease Deposit)           상품 (Merchandise)
   ──────────────────────          ──────────────────────
   (2) 10,000,000 │                (3)  3,000,000 │
                  │                               │
   ──────────────┼──────────      ──────────────┼──────────
   10,000,000    │ 0              3,000,000     │ 0
   잔액: 10,000,000 (차변)        잔액: 3,000,000 (차변)


     매출채권 (Accounts Receivable)         매출 (Sales Revenue)
   ──────────────────────          ──────────────────────
   (4)  8,000,000 │                        │ (4)  8,000,000
                  │                        │
   ──────────────┼──────────      ────────┼──────────────
   8,000,000     │ 0                      │ 8,000,000
   잔액: 8,000,000 (차변)         잔액: 8,000,000 (대변)


          급여 (Salary Expense)
   ──────────────────────
   (5)  4,000,000 │
                  │
   ──────────────┼──────────
   4,000,000     │ 0
   잔액: 4,000,000 (차변)
```

### T계정에서 시산표로

모든 T계정의 잔액을 모아 시산표 (Trial Balance)를 작성할 수 있다:

| 계정과목 | 차변잔액 (Dr.) | 대변잔액 (Cr.) |
|---------|--------------|--------------|
| 현금 | 33,000,000 | |
| 임차보증금 | 10,000,000 | |
| 상품 | 3,000,000 | |
| 매출채권 | 8,000,000 | |
| 자본금 | | 50,000,000 |
| 매출 | | 8,000,000 |
| 급여 | 4,000,000 | |
| **합계** | **58,000,000** | **58,000,000** |

차변 합계와 대변 합계가 일치하므로 기록이 올바르다.

## 실무 분개 예시

실제 세무기장 실무에서 자주 발생하는 거래의 분개 예시를 살펴보자.

### 1. 상품 매출 (현금 + 부가가치세)

상품 1,000,000원 (부가세 별도)을 현금으로 판매했다.

```
(차변) 현금 (Cash)                1,100,000
(대변)   매출 (Sales Revenue)               1,000,000
(대변)   부가세예수금 (VAT Collected)          100,000

적요: 상품 현금 판매 (공급가액 1,000,000원, 부가세 100,000원)
```

매출 금액과 부가가치세 (VAT, Value Added Tax) 10%를 분리하여 기록한다.

### 2. 상품 매입 (외상 + 부가가치세)

원재료 2,000,000원 (부가세 별도)을 외상으로 매입했다.

```
(차변) 상품 (Merchandise)          2,000,000
(차변) 부가세대급금 (VAT Refundable)  200,000
(대변)   매입채무 (Accounts Payable)         2,200,000

적요: 상품 외상 매입 (공급가액 2,000,000원, 부가세 200,000원)
```

매입 시 부담한 부가가치세는 부가세대급금 (자산)으로 기록하여, 향후 매출 부가세에서 차감 (매입세액공제)받는다.

### 3. 급여 지급 (원천징수 포함)

직원 급여 총액 3,500,000원에서 소득세 (Income Tax) 100,000원, 지방소득세 10,000원, 국민건강보험료 (National Health Insurance) 120,000원, 국민연금 (National Pension) 160,000원을 원천징수하고 나머지를 보통예금으로 지급했다.

```
(차변) 급여 (Salary Expense)       3,500,000
(대변)   예수금 (Withholdings)                 390,000
(대변)   보통예금 (Bank Deposit)             3,110,000

적요: 2026년 1월분 급여 지급
     (소득세 100,000 + 지방소득세 10,000 + 건보 120,000 + 연금 160,000 = 390,000 원천징수)
```

> **실무 팁**: 예수금은 세부적으로 소득세예수금, 건강보험예수금, 국민연금예수금 등으로 보조 계정을 두어 관리하기도 한다.

### 4. 사무실 임대료 지급

월 임대료 1,500,000원 (부가세 별도)을 보통예금에서 이체했다.

```
(차변) 임차료 (Rent Expense)       1,500,000
(차변) 부가세대급금 (VAT Refundable)  150,000
(대변)   보통예금 (Bank Deposit)             1,650,000

적요: 2026년 1월분 사무실 임대료 지급
```

### 5. 비품 (컴퓨터) 구입

업무용 노트북 2,500,000원 (부가세 별도)을 법인카드 (미지급금)로 구입했다.

```
(차변) 비품 (Equipment)            2,500,000
(차변) 부가세대급금 (VAT Refundable)  250,000
(대변)   미지급금 (Other Payables)           2,750,000

적요: 업무용 노트북 구입 (법인카드 결제)
```

> **참고**: 소액 비품 (일반적으로 100만 원 미만)은 비품 (자산)이 아닌 소모품비 (비용)로 처리하기도 한다. 세법에서 정하는 즉시 상각 기준을 확인해야 한다.

### 6. 차입금 이자 지급

은행 대출 이자 500,000원이 보통예금에서 자동이체되었다.

```
(차변) 이자비용 (Interest Expense)    500,000
(대변)   보통예금 (Bank Deposit)               500,000

적요: 2026년 1월분 차입금 이자 지급
```

### 7. 외상 매출 대금 회수

거래처로부터 외상 매출 대금 3,300,000원이 보통예금으로 입금되었다.

```
(차변) 보통예금 (Bank Deposit)      3,300,000
(대변)   매출채권 (Accounts Receivable)      3,300,000

적요: (주)ABC 외상 매출 대금 회수
```

### 8. 외상 매입 대금 지급

거래처에 외상 매입 대금 2,200,000원을 보통예금에서 이체했다.

```
(차변) 매입채무 (Accounts Payable)  2,200,000
(대변)   보통예금 (Bank Deposit)             2,200,000

적요: (주)XYZ 외상 매입 대금 결제
```

### 9. 접대비 지급 (법인카드)

거래처 식대 300,000원을 법인카드로 결제했다.

```
(차변) 접대비 (Entertainment Expense)  300,000
(대변)   미지급금 (Other Payables)              300,000

적요: 거래처 (주)ABC 접대 (식대)
```

> **세무 포인트**: 접대비는 세법상 한도가 있다. 기본 한도 (연 3,600만 원)와 수입금액에 따른 추가 한도가 있으며, 한도 초과 접대비는 세무조정 (Tax Adjustment) 시 손금불산입 (Non-deductible Expense)된다.

### 10. 감가상각 (결산 분개)

비품 (컴퓨터)의 월 감가상각비를 인식한다. 취득원가 2,500,000원, 내용연수 (Useful Life) 4년, 정액법 (Straight-line Method).

월 감가상각비 = 2,500,000 ÷ 4년 ÷ 12개월 ≒ 52,083원

```
(차변) 감가상각비 (Depreciation Expense)    52,083
(대변)   감가상각누계액 (Accumulated Depreciation) 52,083

적요: 2026년 1월분 비품 감가상각비 (정액법, 내용연수 4년)
```

### 11. 부가가치세 정산 (결산 분개)

분기별 부가가치세 신고 시, 매출세액에서 매입세액을 차감하여 납부할 세액을 산출한다.

부가세예수금 (매출세액) 500,000원, 부가세대급금 (매입세액) 400,000원인 경우:

```
(차변) 부가세예수금 (VAT Collected)    500,000
(대변)   부가세대급금 (VAT Refundable)         400,000
(대변)   미지급세금 (Tax Payable)              100,000

적요: 2026년 1기 부가가치세 정산 (납부세액 100,000원)
```

### 12. 대손 처리 (매출채권 회수 불능)

거래처 부도로 매출채권 1,000,000원을 회수할 수 없게 되었다.

```
(차변) 대손상각비 (Bad Debt Expense)  1,000,000
(대변)   매출채권 (Accounts Receivable)      1,000,000

적요: (주)DEF 부도에 따른 매출채권 대손 처리
```

> **대손충당금 (Allowance for Doubtful Accounts)** 을 설정한 경우에는 대손충당금을 먼저 차감하고, 부족액을 대손상각비로 처리한다.

## 회계 순환과정 (Accounting Cycle) 요약

분개와 전기는 회계 순환과정의 일부이다. 전체 과정은 다음과 같다:

```
1. 거래 식별 (Identify Transactions)
       │
2. 분개 (Journalize)
       │
3. 전기 (Post to Ledger)
       │
4. 수정전 시산표 (Unadjusted Trial Balance)
       │
5. 수정 분개 (Adjusting Entries)
   - 감가상각, 미지급비용, 선급비용 배분 등
       │
6. 수정후 시산표 (Adjusted Trial Balance)
       │
7. 재무제표 작성 (Financial Statements)
   - 손익계산서 → 재무상태표 → 현금흐름표
       │
8. 마감 분개 (Closing Entries)
   - 수익/비용 계정 잔액을 이익잉여금으로 이전
       │
9. 마감후 시산표 (Post-Closing Trial Balance)
   - 재무상태표 계정만 남음
```

### 수정 분개 (Adjusting Entries)

기말에 발생주의 (Accrual Basis)에 따라 수익과 비용을 적절한 기간에 인식하기 위한 분개이다.

**주요 유형**:

| 유형 | 설명 | 예시 |
|------|------|------|
| 미지급비용 (Accrued Expenses) | 발생했으나 미지급 | 12월분 급여를 1월에 지급 |
| 미수수익 (Accrued Revenue) | 발생했으나 미수취 | 12월분 이자를 1월에 수취 |
| 선급비용 배분 (Prepaid Expenses) | 미리 지급한 비용의 기간 배분 | 1년치 보험료 중 당기 해당분 |
| 선수수익 배분 (Unearned Revenue) | 미리 수취한 수익의 기간 배분 | 1년치 임대료를 선수취 |
| 감가상각 (Depreciation) | 유형자산의 기간별 비용 배분 | 건물, 비품의 감가상각 |

### 마감 분개 (Closing Entries)

기말에 수익과 비용 계정의 잔액을 0으로 만들고, 그 차액 (순이익)을 이익잉여금 (Retained Earnings)으로 이전하는 분개이다.

```
1단계: 수익 계정 마감
(차변) 매출 (Sales Revenue)        8,000,000
(대변)   집합손익 (Income Summary)           8,000,000

2단계: 비용 계정 마감
(차변) 집합손익 (Income Summary)    4,000,000
(대변)   급여 (Salary Expense)               4,000,000

3단계: 집합손익을 이익잉여금으로 이전
(차변) 집합손익 (Income Summary)    4,000,000
(대변)   이익잉여금 (Retained Earnings)      4,000,000
```

순이익 = 수익 8,000,000 - 비용 4,000,000 = 4,000,000원

## 분개 시 흔한 실수와 주의사항

### 흔한 실수

1. **차변/대변 혼동**: 계정의 증감 방향을 잘못 판단하여 반대로 기록
2. **금액 불일치**: 차변과 대변의 합계가 다른 경우
3. **계정과목 오류**: 잘못된 계정과목에 기록 (예: 비품을 소모품비로 처리)
4. **부가세 누락**: 부가가치세를 분리하지 않고 전체 금액을 비용 처리
5. **기간 오류**: 거래를 잘못된 회계기간에 기록

### 주의사항

- **증빙 (Evidence/Voucher)**: 모든 분개에는 반드시 증빙서류가 있어야 한다. 세금계산서 (Tax Invoice), 계산서 (Invoice), 신용카드 매출전표, 현금영수증 (Cash Receipt) 등이 증빙에 해당한다.
- **적요 작성**: 적요는 나중에 거래를 추적할 수 있도록 충분히 구체적으로 작성한다. 거래처명, 거래 내용, 관련 문서 번호 등을 포함한다.
- **부가가치세 분리**: 과세 거래 (Taxable Transaction)의 경우 반드시 공급가액 (Supply Price)과 부가가치세 (VAT)를 분리하여 기록해야 한다.

### 개발자가 알아야 할 것 (What Developers Need to Know)

#### 시스템 설계에 미치는 영향

- **분개는 회계 시스템의 핵심 트랜잭션**이다. 분개 입력 → 검증 → 저장 → 전기의 흐름을 안정적으로 설계해야 한다.
- **자동 분개 (Auto Journal Entry)** 기능이 실무에서 매우 중요하다. 매출/매입 전표 입력 시 부가세 분리, 급여 지급 시 원천징수 계산 등을 자동으로 분개하는 기능이 필요하다.
- **기간 잠금 (Period Lock)**: 마감된 회계기간에는 분개를 추가/수정할 수 없도록 잠금 기능을 구현해야 한다.
- **역분개 (Reversing Entry)**: 분개 수정 시 원본을 직접 수정하지 않고, 원본을 역분개한 후 새로운 분개를 입력하는 방식으로 처리하여 감사추적 (Audit Trail)을 유지한다.

#### 데이터 모델링 포인트

```sql
-- 분개 헤더 (Journal Entry Header)
CREATE TABLE journal_entry (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT,
    entry_number    VARCHAR(20) UNIQUE NOT NULL,  -- 전표번호
    entry_date      DATE NOT NULL,                 -- 거래일자
    entry_type      VARCHAR(20),                   -- 전표유형: GENERAL, SALES, PURCHASE, CASH 등
    description     VARCHAR(500),                  -- 적요
    fiscal_year     INT NOT NULL,                  -- 회계연도
    fiscal_month    INT NOT NULL,                  -- 회계월
    status          VARCHAR(20) DEFAULT 'DRAFT',   -- 상태: DRAFT, POSTED, REVERSED
    reversed_by     BIGINT,                        -- 역분개 전표 ID
    created_at      TIMESTAMP DEFAULT NOW(),
    created_by      VARCHAR(100),
    approved_at     TIMESTAMP,
    approved_by     VARCHAR(100)
);

-- 분개 상세 (Journal Entry Line)
CREATE TABLE journal_entry_line (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT,
    journal_entry_id BIGINT NOT NULL,
    line_number     INT NOT NULL,                   -- 행 번호
    account_code    VARCHAR(10) NOT NULL,           -- 계정과목 코드
    debit_amount    BIGINT DEFAULT 0,               -- 차변 금액 (원 단위)
    credit_amount   BIGINT DEFAULT 0,               -- 대변 금액 (원 단위)
    description     VARCHAR(200),                   -- 행 적요
    partner_name    VARCHAR(100),                   -- 거래처명
    evidence_type   VARCHAR(50),                    -- 증빙유형
    evidence_number VARCHAR(50),                    -- 증빙번호
    FOREIGN KEY (journal_entry_id) REFERENCES journal_entry(id),
    CHECK (debit_amount >= 0 AND credit_amount >= 0),
    CHECK (NOT (debit_amount > 0 AND credit_amount > 0))
);

-- 총계정원장 (자동 집계 뷰)
CREATE VIEW general_ledger AS
SELECT
    jel.account_code,
    a.name_kr AS account_name,
    je.entry_date,
    je.entry_number,
    jel.description,
    jel.debit_amount,
    jel.credit_amount,
    SUM(jel.debit_amount - jel.credit_amount)
        OVER (PARTITION BY jel.account_code ORDER BY je.entry_date, je.id) AS running_balance
FROM journal_entry_line jel
JOIN journal_entry je ON je.id = jel.journal_entry_id
JOIN account a ON a.code = jel.account_code
WHERE je.status = 'POSTED';
```

- **전표번호 (Entry Number)**: 고유하고 순차적인 번호 체계 (예: `JE-2026-00001`)가 필요하다.
- **상태 관리 (Status)**: DRAFT → POSTED → REVERSED의 상태 전이를 관리한다.
- **총계정원장은 뷰 (View)로 구현**할 수 있다. 분개 데이터를 계정별로 집계하면 원장이 된다.

#### ERP/회계 프로그램 연동 시 참고 사항

- **더존 (Douzone)**, **세무사랑 (Taxmate)** 등에서는 전표 유형을 **입금전표, 출금전표, 대체전표** 등으로 구분한다. API 연동 시 전표 유형 매핑이 필요하다.
- **전자세금계산서 (e-Tax Invoice)** 수신 시 매입 분개를 자동 생성하는 기능이 실무에서 매우 유용하다.
- **은행 거래 내역 (Bank Statement)** 자동 수집 후 분개를 제안하는 **자동 분개 추천 (Auto Journal Suggestion)** 기능은 세무기장 효율을 크게 높인다.
- 분개 데이터를 엑셀 또는 CSV로 **일괄 가져오기 (Bulk Import)** 하는 기능도 필수적이다. 형식 검증, 대차 균형 검증을 반드시 포함해야 한다.

### 용어 사전 (Glossary)

| 한글 | 영문 | 설명 |
|------|------|------|
| 분개 | Journal Entry | 거래를 차변과 대변으로 나누어 기록하는 것 |
| 전기 | Posting | 분개장의 기록을 총계정원장으로 옮기는 과정 |
| 분개장 | Journal | 거래 발생 순서대로 분개를 기록하는 장부 |
| 총계정원장 | General Ledger (GL) | 계정과목별로 거래를 정리한 장부 |
| T계정 | T-Account | 원장 계정을 T자 형태로 간략하게 표현한 학습 도구 |
| 적요 | Description / Narration | 거래의 내용을 간략히 설명하는 텍스트 |
| 전표 | Voucher / Slip | 분개를 기록한 문서 (입금/출금/대체 전표) |
| 증빙 | Evidence / Supporting Document | 거래를 뒷받침하는 서류 (세금계산서, 영수증 등) |
| 복합분개 | Compound Journal Entry | 차변 또는 대변이 2개 이상인 분개 |
| 수정 분개 | Adjusting Entry | 기말에 발생주의에 따라 수익/비용을 조정하는 분개 |
| 마감 분개 | Closing Entry | 수익/비용 계정을 이익잉여금으로 이전하는 기말 분개 |
| 역분개 | Reversing Entry | 기존 분개를 취소하기 위해 차변/대변을 반대로 기록 |
| 발생주의 | Accrual Basis | 현금 수수와 관계없이 거래 발생 시점에 인식하는 원칙 |
| 원천징수 | Withholding Tax | 소득 지급 시 세금을 미리 공제하여 납부하는 제도 |
| 집합손익 | Income Summary | 마감 시 수익/비용을 집계하기 위한 임시 계정 |
