# 대역폭 (Bandwidth)

네트워크에서 자주 혼동되는 개념인 **대역폭(Bandwidth)**과 **처리량(Throughput)**의 차이점을 정리한다.

## 핵심 개념

### 대역폭 (Bandwidth)

- 네트워크가 **이론적으로 전송할 수 있는 최대 데이터량**
- 도로의 **차선 수**에 비유할 수 있음
- 단위: bps (bits per second), Mbps, Gbps
- 물리적 매체(케이블, 무선 주파수 등)에 의해 결정됨

### 처리량 (Throughput)

- 네트워크에서 **실제로 전송되는 데이터량**
- 도로에서 **실제로 이동하는 차량 수**에 비유할 수 있음
- 단위: bps (bits per second), Mbps, Gbps
- 네트워크 상태에 따라 실시간으로 변동

## 대역폭 vs 처리량 비교

| 구분 | 대역폭 (Bandwidth) | 처리량 (Throughput) |
|------|-------------------|---------------------|
| **정의** | 최대 전송 가능 용량 | 실제 전송된 데이터량 |
| **성격** | 이론적/고정값 | 실측값/가변적 |
| **비유** | 고속도로의 차선 수 | 실제 통과하는 차량 수 |
| **영향 요인** | 물리적 인프라 | 네트워크 혼잡, 패킷 손실, 지연 |
| **측정 시점** | 설계/계약 시 | 실시간 모니터링 |

## 대역폭의 종류

### 전용 대역폭 (Dedicated Bandwidth)

- 특정 사용자나 서비스에 **독점적으로 할당**된 대역폭
- 다른 트래픽의 영향을 받지 않음
- 기업용 전용선, 클라우드 Direct Connect 등
- 비용이 높지만 안정적인 성능 보장

### 공유 대역폭 (Shared Bandwidth)

- 여러 사용자가 **함께 사용**하는 대역폭
- 가정용 인터넷, 공용 WiFi 등
- 사용자가 많아지면 개인당 사용 가능 대역폭 감소
- 비용 효율적이지만 성능 변동 있음

### 대칭/비대칭 대역폭

| 유형 | 업로드 | 다운로드 | 사용 예 |
|------|--------|----------|---------|
| **대칭 (Symmetric)** | 100Mbps | 100Mbps | 기업용, 서버 호스팅 |
| **비대칭 (Asymmetric)** | 10Mbps | 100Mbps | 가정용 인터넷, ADSL |

## 대역폭과 지연 시간의 관계

### 지연 시간 (Latency)

- 데이터가 출발지에서 목적지까지 도달하는 데 걸리는 **시간**
- 단위: ms (밀리초)
- 대역폭과는 독립적인 개념

### 비유로 이해하기

```
대역폭 = 파이프의 굵기 (한 번에 얼마나 많이)
지연 시간 = 파이프의 길이 (얼마나 빨리 도착하는지)
처리량 = 실제로 흐르는 물의 양
```

### 예시: 대역폭 vs 지연 시간

| 시나리오 | 대역폭 | 지연 시간 | 적합한 용도 |
|----------|--------|-----------|-------------|
| 위성 인터넷 | 높음 (100Mbps) | 높음 (600ms) | 대용량 다운로드 |
| 광케이블 | 높음 (1Gbps) | 낮음 (5ms) | 실시간 게임, 화상회의 |
| 3G 모바일 | 낮음 (2Mbps) | 중간 (100ms) | 기본 웹 브라우징 |

## 대역폭 계산

### 데이터 전송 시간 계산

```
전송 시간 = 파일 크기 / 대역폭

예시:
- 파일 크기: 1GB = 8Gb (8 × 1024Mb)
- 대역폭: 100Mbps
- 이론적 전송 시간: 8192Mb / 100Mbps = 약 82초
```

### 단위 변환

| 단위 | 값 |
|------|-----|
| 1 Byte | 8 bits |
| 1 KB | 1,024 Bytes |
| 1 MB | 1,024 KB |
| 1 Mbps | 1,000,000 bits/sec |
| 1 Gbps | 1,000 Mbps |

> **주의**: 네트워크 속도는 **bits**, 파일 크기는 **Bytes**로 표기하므로 변환 필요

## 실제 예시

```
인터넷 회선: 100Mbps (대역폭)
    ↓
실제 다운로드 속도: 80Mbps (처리량)
    ↓
손실: 20Mbps (네트워크 오버헤드, 혼잡 등)
```

## 처리량에 영향을 주는 요인

| 요인 | 설명 | 개선 방법 |
|------|------|-----------|
| **네트워크 혼잡** | 동시 사용자가 많을수록 처리량 감소 | QoS 설정, 트래픽 분산 |
| **패킷 손실** | 재전송으로 인한 효율 저하 | 네트워크 장비 점검, 케이블 교체 |
| **지연 시간(Latency)** | 왕복 시간이 길수록 전송 효율 감소 | CDN 사용, 서버 위치 최적화 |
| **프로토콜 오버헤드** | TCP 헤더, IP 헤더 등의 추가 데이터 | 프로토콜 최적화 |
| **하드웨어 성능** | 라우터, 스위치 처리 능력 | 장비 업그레이드 |
| **MTU 설정** | 최대 전송 단위 불일치 | MTU 최적화 (일반적으로 1500 bytes) |

## 대역폭 측정 도구

### CLI 도구

```bash
# iperf3 - 네트워크 성능 측정
iperf3 -c speedtest.example.com

# speedtest-cli
speedtest-cli

# curl로 다운로드 속도 측정
curl -o /dev/null -w "속도: %{speed_download}\n" https://example.com/largefile
```

### 웹 기반 도구

- **Speedtest.net**: 가장 널리 사용되는 속도 측정
- **Fast.com**: Netflix 제공, 간편한 측정
- **Cloudflare Speed Test**: 상세한 네트워크 분석

## 대역폭 관련 기술

### QoS (Quality of Service)

특정 트래픽에 우선순위를 부여하여 대역폭 할당 관리

```
[높은 우선순위] 화상회의, VoIP
[중간 우선순위] 웹 브라우징
[낮은 우선순위] 파일 다운로드, 백업
```

### 대역폭 제한 (Throttling)

- ISP나 관리자가 의도적으로 대역폭을 제한
- 공정한 사용을 위해 또는 네트워크 과부하 방지 목적
- 특정 서비스(P2P, 스트리밍)에 선별적 적용 가능

## 요약

- **대역폭**: "얼마나 넓은 길인가" (최대 용량)
- **처리량**: "실제로 얼마나 빠르게 가고 있는가" (실제 속도)
- **지연 시간**: "얼마나 빨리 도착하는가" (응답 속도)
- 처리량은 항상 대역폭보다 작거나 같다: `처리량 ≤ 대역폭`
- 용도에 따라 대역폭과 지연 시간 중 더 중요한 것이 다름
