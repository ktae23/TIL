## 1. EC2 구매 옵션

### On-Demand

```
특징:
- 시간당(또는 초당) 과금
- 약정 없음
- 즉시 시작/종료

사용 사례:
- 단기 워크로드
- 예측 불가 패턴
- 테스트/개발 환경

비용: 기준가 (100%)
```

### Reserved Instances (RI)

```
특징:
- 1년 또는 3년 약정
- 특정 인스턴스 유형/리전 예약
- 용량 예약 옵션

약정 유형:
- All Upfront: 전액 선불 → 최대 할인
- Partial Upfront: 일부 선불 → 중간 할인
- No Upfront: 선불 없음 → 적은 할인

할인율:
- 1년: 최대 42%
- 3년: 최대 72%
```

### Spot Instances

```
특징:
- AWS 여유 용량 활용
- 최대 90% 할인
- 언제든 중단 가능 (2분 경고)

사용 사례:
- 배치 작업
- 데이터 분석
- CI/CD
- 무상태 웹 서버

중단 대응:
- Spot 중단 알림 활용
- 체크포인트 저장
- Auto Scaling 그룹
```

### 비교표

| 옵션 | 할인율 | 약정 | 안정성 | 사용 사례 |
|------|--------|------|--------|----------|
| On-Demand | 0% | 없음 | 높음 | 단기, 테스트 |
| Reserved | ~72% | 1-3년 | 높음 | 상시 운영 |
| Spot | ~90% | 없음 | 낮음 | 배치, 분석 |

### 혼합 전략

```
권장 구성:
┌─────────────────────────────────────────┐
│     On-Demand (10-20%)                  │ ← 피크 대응
├─────────────────────────────────────────┤
│     Spot (20-30%)                       │ ← 유연한 워크로드
├─────────────────────────────────────────┤
│     Reserved / Savings Plans (50-70%)   │ ← 기본 용량
└─────────────────────────────────────────┘
```

## 2. Savings Plans

### 유형

```
Compute Savings Plans:
- 시간당 컴퓨팅 사용량 약정
- EC2, Fargate, Lambda 적용
- 인스턴스 유형/리전 유연
- 최대 66% 할인

EC2 Instance Savings Plans:
- 특정 인스턴스 패밀리/리전 약정
- 인스턴스 크기는 유연
- 최대 72% 할인
```

### RI vs Savings Plans

| 특성 | Reserved Instances | Savings Plans |
|------|-------------------|---------------|
| 유연성 | 낮음 | 높음 |
| 적용 범위 | EC2만 | EC2, Fargate, Lambda |
| 관리 | 복잡 | 단순 |
| 할인율 | 약간 높음 | 약간 낮음 |

### 권장 사용

```
신규 사용자: Savings Plans 권장 (관리 용이)
복잡한 환경: Compute Savings Plans
단순한 환경: EC2 Instance Savings Plans
```

## 3. 스토리지 최적화

### S3 스토리지 클래스

```
┌─────────────────────────────────────────────────────────────┐
│ 접근 빈도            스토리지 클래스          비용           │
├─────────────────────────────────────────────────────────────┤
│ 빈번함    ←──────── Standard ──────────→  높음             │
│                                                             │
│            ←── Standard-IA ────→                           │
│                                                             │
│            ←── One Zone-IA ───→                            │
│                                                             │
│            ←── Glacier Instant ─→                          │
│                                                             │
│            ←── Glacier Flexible ─→                         │
│                                                             │
│ 드뭄      ←── Glacier Deep Archive ─→  낮음                │
└─────────────────────────────────────────────────────────────┘
```

### 수명 주기 정책

```json
{
    "Rules": [
        {
            "ID": "ArchiveOldLogs",
            "Status": "Enabled",
            "Filter": {
                "Prefix": "logs/"
            },
            "Transitions": [
                {
                    "Days": 30,
                    "StorageClass": "STANDARD_IA"
                },
                {
                    "Days": 90,
                    "StorageClass": "GLACIER"
                }
            ],
            "Expiration": {
                "Days": 365
            }
        }
    ]
}
```

### EBS 최적화

```
볼륨 유형 선택:
- gp3: 범용 (gp2 대비 20% 저렴)
- io2: 고성능 필요 시만
- st1/sc1: 대용량 순차 읽기

최적화 전략:
- 미사용 볼륨 삭제
- 스냅샷 정리
- gp2 → gp3 마이그레이션
- 볼륨 크기 적정화
```

## 4. 비용 모니터링

### AWS Cost Explorer

```
기능:
- 비용 시각화
- 서비스/리전/태그별 분석
- 예측
- RI/SP 권장사항

활용:
- 월별 트렌드 분석
- 이상 비용 탐지
- 예산 대비 확인
```

### AWS Budgets

```
예산 유형:
- 비용 예산
- 사용량 예산
- RI 활용률 예산
- Savings Plans 활용률 예산

알림 설정:
- 임계값 초과 시 이메일/SNS
- 예측 기반 알림
- 실제 사용량 기반 알림
```

### Cost Allocation Tags

```
태그 활성화:
1. Billing Console → Cost Allocation Tags
2. User-Defined Tags 활성화

권장 태그:
- Environment: production/staging/development
- Project: project-name
- Owner: team-name
- CostCenter: cost-center-code

활용:
- 프로젝트별 비용 추적
- 팀별 비용 할당
- 환경별 비용 분석
```

### Trusted Advisor

```
비용 최적화 체크:
- 미사용 EC2 인스턴스
- 미사용 EBS 볼륨
- 미사용 Elastic IP
- 유휴 RDS 인스턴스
- 미활용 RI
```

## 5. 아키텍처 최적화

### 적정 사이징

```
방법:
1. CloudWatch 메트릭 분석
   - CPU 사용률
   - 메모리 사용률
   - 네트워크 I/O

2. Compute Optimizer 활용
   - 자동 분석
   - 다운사이징 권장

3. 주기적 검토
   - 월별 또는 분기별
   - 사용 패턴 변화 반영
```

### 서버리스 전환

```
비용 효율적인 경우:
- 간헐적 트래픽
- 이벤트 기반 처리
- 빠른 스케일링 필요

Lambda 비용 최적화:
- 메모리 적정화 (Power Tuning)
- Provisioned Concurrency 검토
- ARM 기반 (Graviton2) 사용
```

### 데이터 전송 최적화

```
비용 발생 구간:
- 인터넷 아웃바운드
- 리전 간 전송
- AZ 간 전송 (일부)

최적화:
- CloudFront 활용 (캐싱)
- VPC Endpoint 사용
- 동일 AZ 배치
- 데이터 압축
```

## 6. 비용 절감 체크리스트

### 즉시 실행

```
□ 미사용 리소스 정리
  - 중지된 EC2
  - 연결 안 된 EBS
  - 미사용 Elastic IP
  - 오래된 스냅샷

□ 적정 사이징
  - Compute Optimizer 확인
  - 과다 프로비저닝 인스턴스 축소

□ 스토리지 최적화
  - S3 수명 주기 정책
  - gp2 → gp3 전환
```

### 단기 (1-3개월)

```
□ Reserved Instances / Savings Plans 구매
  - 안정적 워크로드 분석
  - 1년 약정부터 시작

□ Spot 인스턴스 도입
  - 배치 작업
  - 개발/테스트 환경

□ 태그 정책 수립
  - 필수 태그 정의
  - 비용 할당 활성화
```

### 장기 (3개월+)

```
□ 아키텍처 검토
  - 서버리스 전환 가능성
  - 컨테이너화
  - 마이크로서비스

□ 멀티 리전 최적화
  - 데이터 전송 비용
  - 리전별 가격 차이

□ 라이선스 최적화
  - BYOL 검토
  - 오픈소스 대안
```
