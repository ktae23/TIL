# Week 13: 비즈니스 커뮤니케이션

---

## Lesson 33 — 비즈니스 이메일 작성법

---

### 1. WHY — 왜 영어 이메일은 한국어와 구조가 다른가

한국어 이메일은 보통 이렇게 시작한다:

```
안녕하세요, OO팀 김OO 대리님.
바쁘신 와중에 메일 드려 죄송합니다.
다름이 아니라, 지난번 말씀드린 건 관련하여...
```

영어 이메일은 전혀 다른 구조를 따른다:

```
Hi Sarah,

I'm writing to follow up on the project timeline we discussed last Monday.
Could you share the updated schedule by Friday?

Thanks,
James
```

**핵심 차이점:**

| 한국어 이메일 | 영어 이메일 |
|---|---|
| 인사 + 사과/겸양으로 시작 | 간결한 인사 후 바로 본론 |
| 맥락 설명이 길다 | 첫 문장에서 목적을 밝힌다 |
| 마무리에 "부탁드립니다" | 구체적 Action item을 제시 |
| 존칭이 복잡하다 | Dear/Hi + 이름으로 단순화 |

영어 이메일의 황금 규칙은 **"Bottom Line Up Front (BLUF)"** 이다. 결론을 먼저 말하고, 배경 설명은 그 다음이다. 한국어 사고방식("맥락 먼저, 결론 나중에")을 영어에 그대로 적용하면, 상대방은 "도대체 무슨 말을 하고 싶은 거지?"라고 느낀다.

> **핵심 원리**: "영어 이메일은 신문 기사와 같다. 헤드라인(제목)으로 핵심을 전달하고, 첫 문단에서 결론을 밝히고, 이후에 세부 내용을 덧붙인다."

---

### 2. CORE — 이메일의 기본 구조

영어 이메일은 **5개 블록**으로 구성된다:

```
┌─────────────────────────────────────────┐
│ 1. Subject Line (제목)                  │  ← 이메일의 운명을 결정
│ 2. Greeting (인사)                      │  ← 관계에 맞는 톤 설정
│ 3. Body (본문)                          │  ← 목적 → 세부사항 → 요청
│ 4. Closing (마무리)                     │  ← 다음 단계(Action) 명시
│ 5. Sign-off (서명)                      │  ← 적절한 격식으로 마감
└─────────────────────────────────────────┘
```

---

#### Block 1: Subject Line (제목)

제목은 이메일의 첫인상이다. 바쁜 사람은 제목만 보고 열지 말지 결정한다.

**좋은 제목의 원칙:**
- 구체적이어야 한다 (Meeting → Q1 Budget Meeting — March 15, 2pm)
- 행동이 명확해야 한다 (Action Required / For Your Review / FYI)
- 10단어 이내로 쓴다

| 나쁜 제목 | 좋은 제목 |
|---|---|
| Hello | Meeting Request: Project Kickoff — March 20 |
| Question | Question About the Q2 Marketing Budget |
| Important | Action Required: Submit Expense Reports by Friday |
| Update | Weekly Status Update — Design Team (Feb 10) |
| Request | Request for Approval: New Vendor Contract |

---

#### Block 2: Greeting (인사)

격식 수준에 따라 선택한다:

| 격식 수준 | 표현 | 사용 상황 |
|---|---|---|
| 매우 격식 | Dear Mr. Kim, / Dear Ms. Park, | 처음 연락, 공식 서신 |
| 격식 | Dear Sarah, | 이름을 아는 외부인 |
| 보통 | Hi Sarah, / Hello Team, | 일반 업무 이메일 |
| 캐주얼 | Hey James, | 친한 동료 |
| 그룹 | Hi everyone, / Dear all, | 팀 전체 |

> **주의**: "Dear Sir/Madam"은 수신자를 모를 때만 쓴다. 이름을 알면서 이렇게 쓰면 거리감이 느껴진다.

---

#### Block 3: Body (본문)

**첫 문장 = 목적 문장 (Purpose Statement)**

이메일을 쓰는 이유를 첫 줄에 밝힌다:

```
I'm writing to request a meeting to discuss the new project timeline.
I'm reaching out to follow up on our conversation last week.
I'd like to share an update on the current progress.
I wanted to let you know that the deadline has been extended.
```

**중간 = 세부 내용 (Details)**

구체적 정보를 제공한다. 항목이 여러 개면 번호나 글머리 기호를 사용한다:

```
There are three items I'd like to discuss:
1. The revised budget for Q2
2. The timeline for the product launch
3. The allocation of resources across teams
```

**마지막 = 요청/다음 단계 (Call to Action)**

상대에게 원하는 행동을 명확히 요청한다:

```
Could you please review the attached document and share your feedback by Thursday?
Please let me know if this time works for you.
I'd appreciate it if you could confirm by end of day.
```

---

#### Block 4–5: Closing + Sign-off

| 격식 수준 | Closing + Sign-off |
|---|---|
| 매우 격식 | I look forward to hearing from you. / Sincerely, |
| 격식 | Thank you for your time. / Best regards, |
| 보통 | Thanks! / Best, |
| 캐주얼 | Talk soon! / Cheers, |

---

### 3. PATTERNS — 상황별 핵심 패턴

#### Pattern 1: 요청 (Request)

```
격식: I would like to request your assistance with the quarterly report.
보통: Could you please send me the latest version of the file?
캐주얼: Can you share that document with me?
```

**요청의 강도 조절:**

| 약함 (공손) → 강함 (직접) |
|---|
| I was wondering if you could possibly review this. |
| I would appreciate it if you could review this. |
| Could you please review this? |
| Please review this by Friday. |
| I need you to review this by Friday. |

> **Phase 2에서 배운 조동사 복습**: could/would는 공손함의 거리감을 만든다. "Can you~"보다 "Could you~"가 더 정중한 이유는 과거형이 심리적 거리를 만들기 때문이다.

---

#### Pattern 2: 회신 (Response)

```
Thank you for your email regarding the upcoming conference.
In response to your inquiry, I'd like to provide the following information.
Thank you for getting back to me so quickly.
I appreciate you sharing the details.
```

---

#### Pattern 3: 감사 (Appreciation)

```
I appreciate your prompt response.
Thank you for taking the time to review the proposal.
I'm grateful for your support on this project.
Many thanks for your help with the presentation.
```

---

#### Pattern 4: 사과 (Apology)

```
I apologize for the inconvenience.
I'm sorry for the delayed response.
I apologize for any confusion my previous email may have caused.
Please accept my apologies for missing the meeting yesterday.
```

**사과 후에는 반드시 해결책/다음 단계를 제시한다:**

```
I apologize for the delay in sending the report.
I've attached the updated version, and I've also included the additional data you requested.
```

---

#### Pattern 5: 마감 알림 (Deadline Reminder)

```
Please note that the deadline is this Friday, March 15.
This is a friendly reminder that the submission is due by end of day Thursday.
Just a quick reminder that we need your input by March 20.
I wanted to remind you that the deadline for the survey is approaching.
```

### 4. APPLY — 실전 이메일 예시 (5가지 상황)

#### 예시 1: 회의 요청 (Meeting Request)

```
Subject: Meeting Request: Q2 Planning Discussion — Week of March 17

Hi Sarah,

I'd like to schedule a meeting to discuss the Q2 marketing plan.
Specifically, I'd like to cover the following topics:

1. Budget allocation for digital campaigns
2. Timeline for the product launch event
3. Team responsibilities and deliverables

Would any time on Tuesday or Wednesday afternoon work for you?
The meeting should take about 30 minutes.

Looking forward to hearing from you.

Best regards,
James
```

**문법 포인트**: "I'd like to~" (Phase 2의 would like to), "Would any time work~?" (가정법적 공손 표현)

---

#### 예시 2: 후속 조치 (Follow-up)

```
Subject: Follow-up: Action Items from Monday's Team Meeting

Hi Team,

Thank you all for a productive meeting on Monday.
I wanted to summarize the key action items we agreed on:

- David: Finalize the budget spreadsheet by March 14
- Emily: Share the competitor analysis by March 16
- James: Set up the client presentation for March 20

Please let me know if I've missed anything or if the deadlines
need to be adjusted.

Thanks,
James
```

**문법 포인트**: "I wanted to~" (과거형으로 공손함 표현), "if I've missed~" (현재완료 + 가정)

---

#### 예시 3: 마감 알림 (Deadline Reminder)

```
Subject: Reminder: Expense Reports Due This Friday

Hi everyone,

This is a friendly reminder that all expense reports for February
must be submitted through the system by this Friday, March 14.

If you have any questions about the submission process,
please don't hesitate to reach out to the finance team.

Late submissions may delay the reimbursement process,
so I'd appreciate it if everyone could submit on time.

Thank you for your cooperation.

Best,
James
```

**문법 포인트**: "must be submitted" (수동태, Phase 3), "I'd appreciate it if~" (가정법적 공손 표현, Phase 5)

---

#### 예시 4: 감사 이메일 (Thank-you)

```
Subject: Thank You for Your Support on the Project

Dear Ms. Park,

I wanted to take a moment to thank you for your invaluable support
during the product launch last week.

Your expertise in coordinating the logistics made a significant
difference, and the event was a great success thanks to your efforts.

I look forward to working with you on future projects.

Sincerely,
James Kim
```

**문법 포인트**: "I wanted to take a moment to~" (공손한 목적 표현), "made a significant difference" (실전 콜로케이션)

---

#### 예시 5: 사과 이메일 (Apology)

```
Subject: Apology for the Delayed Report Submission

Hi Sarah,

I sincerely apologize for the delay in submitting the monthly report.
Due to an unexpected system issue, I was unable to access the data
I needed to complete the analysis on time.

The issue has been resolved, and I've attached the completed report
to this email. I've also included the supplementary data you
requested in our last conversation.

I'll make sure to plan ahead next month to avoid any similar delays.
Please let me know if you need any additional information.

Best regards,
James
```

**문법 포인트**: "Due to~" (원인 표현), "has been resolved" (현재완료 수동태), "I'll make sure to~" (미래 의지)

> 상황: 팀 회의 후 3가지 Action Item을 정리하여 팀원들에게 공유한다. 각 항목에 담당자와 마감일을 포함한다.

## Lesson 34 — 회의와 프레젠테이션 영어

---

### 1. WHY — 영어 회의에서 한국인이 어려워하는 점

한국어 회의 문화와 영어 회의 문화는 근본적으로 다르다:

| 한국어 회의 | 영어 회의 |
|---|---|
| 상사가 주로 발언, 부하는 경청 | 모두가 적극적으로 발언하길 기대 |
| 침묵은 "경청/존중"으로 해석 | 침묵은 "관심 없음/이해 못함"으로 해석 |
| 반대 의견은 간접적으로 돌려 말함 | 반대 의견도 직접적으로 표현 (단, 공손하게) |
| "네, 알겠습니다"로 마무리 | "So, just to confirm..." 으로 확인 |
| 회의 후 실질적 논의가 이루어짐 | 회의 중에 결정을 내림 |

한국인이 영어 회의에서 겪는 3대 어려움:

1. **발언 타이밍을 못 잡는다** — "끼어들기"가 무례하다고 느낀다
2. **반대 의견 표현이 어렵다** — "I disagree"가 너무 직접적으로 느껴진다
3. **즉석 정리/요약이 안 된다** — 들은 내용을 바로 영어로 정리하는 연습이 부족하다

> **핵심 원리**: "영어 회의에서는 '발언하는 것'이 참여하는 것이다. 고개만 끄덕이면 존재감이 없어진다. 짧은 한마디라도 말하는 것이 핵심이다."

---

### 2. CORE — 회의 영어의 기본 패턴

회의 영어는 **7가지 기능**으로 분류할 수 있다. 각 기능별 핵심 패턴을 익혀두면 어떤 회의에서든 활용할 수 있다.

---

#### 기능 1: 의견 제시 (Stating Opinions)

확신 정도에 따라 표현이 달라진다:

| 확신 높음 → 낮음 | 표현 |
|---|---|
| 강한 확신 | I'm confident that this approach will work. |
| 보통 확신 | I think we should focus on the core features first. |
| 조심스러운 의견 | In my opinion, it might be better to wait. |
| 겸손한 의견 | From my perspective, there could be a simpler solution. |
| 매우 조심스러운 | I may be wrong, but I feel like we need more data. |

**실전 예문:**

```
I think the current timeline is too tight.
(현재 일정이 너무 빡빡하다고 생각합니다.)

In my opinion, we should prioritize user feedback before moving forward.
(제 의견으로는, 진행하기 전에 사용자 피드백을 우선시해야 합니다.)

From my perspective, the design needs a few more iterations.
(제 관점에서, 디자인은 몇 번 더 반복 작업이 필요합니다.)

Based on my experience, this kind of issue usually takes about two weeks to resolve.
(제 경험상, 이런 종류의 이슈는 보통 해결하는 데 약 2주가 걸립니다.)
```

---

#### 기능 2: 동의 (Agreeing)

단순 "I agree" 외에도 다양한 표현이 있다:

```
I agree with Sarah's point about the timeline.
(일정에 대한 Sarah의 의견에 동의합니다.)

That's a good point. I hadn't thought of it that way.
(좋은 지적이네요. 그렇게는 생각해보지 못했습니다.)

I completely agree. That's exactly what I was thinking.
(전적으로 동의합니다. 저도 정확히 그렇게 생각하고 있었습니다.)

You make a valid point. Let's explore that further.
(타당한 지적이십니다. 그 부분을 더 살펴봅시다.)

That makes a lot of sense, especially considering the budget constraints.
(예산 제약을 고려하면 정말 일리가 있네요.)
```

**동의 + 추가 의견 패턴** (매우 유용):

```
I agree with that, and I'd also like to add that we need to consider
the user experience as well.
(동의합니다. 그리고 사용자 경험도 고려해야 한다는 점을 추가하고 싶습니다.)

That's a great idea. Building on that, what if we also included
a feedback mechanism?
(좋은 아이디어입니다. 거기에 더해서, 피드백 메커니즘도 포함하면 어떨까요?)
```

---

#### 기능 3: 반대 (Disagreeing — politely)

영어에서도 무작정 "I disagree"라고 하면 강하게 느껴질 수 있다. **부드러운 반대** 패턴을 익혀야 한다:

```
[인정] + [but/however] + [반대 의견]
```

| 부드러움 정도 | 표현 |
|---|---|
| 매우 부드러움 | I see your point, but I'm wondering if there might be another way. |
| 부드러움 | That's an interesting idea. However, I have some concerns about the cost. |
| 보통 | I understand where you're coming from, but I think we need to consider the risks. |
| 약간 직접적 | I'm not sure I agree with that approach. Here's my concern: ... |
| 직접적 | I respectfully disagree. I think the data suggests a different direction. |

**실전 대화 예시:**

```
A: I think we should launch the product next month.
B: I see your point, and I understand the urgency. However,
   I'm a bit concerned that we haven't finished the testing phase yet.
   Would it be possible to push the launch by two weeks
   to make sure everything is solid?
```

> **Phase 5 복습**: "Would it be possible~"은 가정법적 공손 표현이다. "Is it possible~"보다 한 단계 더 공손하다.

---

#### 기능 4: 질문 (Asking Questions)

회의에서 질문은 **참여의 신호**다. 적극적으로 질문하자:

```
확인 질문:
Could you elaborate on that point?
(그 부분을 좀 더 자세히 설명해주시겠어요?)

What do you mean by "scalable"?
(여기서 "scalable"이라는 게 구체적으로 무슨 뜻인가요?)

Just to clarify, are you saying that we need to change the entire approach?
(확인차 여쭤보는데, 전체 접근 방식을 바꿔야 한다는 말씀이신가요?)

탐색 질문:
How would that work in practice?
(실제로 그건 어떻게 작동하나요?)

What would be the impact on the current timeline?
(현재 일정에 어떤 영향이 있을까요?)

Have we considered the alternative of outsourcing this part?
(이 부분을 외주로 돌리는 대안은 검토해봤나요?)
```

---

#### 기능 5: 정리/요약 (Summarizing)

회의 중간이나 마무리에 핵심을 정리하는 능력은 매우 중요하다:

```
To summarize what we've discussed so far, we have three main action items.
(지금까지 논의한 내용을 정리하면, 주요 Action Item이 3가지 있습니다.)

Let me recap the key points from today's meeting.
(오늘 회의의 핵심 사항을 정리하겠습니다.)

So, if I understand correctly, we're going to postpone the launch
and focus on testing first. Is that right?
(제가 올바르게 이해한 거라면, 출시를 미루고 테스팅에 먼저 집중하는 거죠. 맞나요?)

Just to make sure we're all on the same page:
the deadline is March 20, and David is leading this initiative.
(우리 모두 같은 이해를 하고 있는지 확인하자면: 마감은 3월 20일이고, David가 이 건을 리드합니다.)
```

---

#### 기능 6: 제안 (Making Suggestions)

```
How about we split the work into two phases?
(작업을 2단계로 나누는 건 어떨까요?)

I suggest we schedule a follow-up meeting next week.
(다음 주에 후속 회의를 잡자고 제안합니다.)

What if we tried a different approach for the user interface?
(UI에 다른 접근법을 시도해보면 어떨까요?)

Why don't we get the client's feedback before making a final decision?
(최종 결정 전에 클라이언트 피드백을 받는 게 어떨까요?)

One option could be to hire a freelancer for this specific task.
(한 가지 옵션은 이 특정 업무에 프리랜서를 고용하는 것일 수 있습니다.)
```

---

#### 기능 7: 끼어들기 (Interrupting — politely)

한국인에게 가장 어려운 부분이다. 하지만 영어 회의에서는 적절한 끼어들기가 허용된다:

```
Sorry to interrupt, but I have a quick point about that.
(끼어들어서 죄송한데, 그 점에 대해 잠깐 말씀드릴 게 있습니다.)

If I may add something here...
(여기서 한 가지 추가해도 될까요...)

Before we move on, I'd like to mention one thing.
(넘어가기 전에, 한 가지 말씀드리고 싶습니다.)

Can I jump in here for a second?
(잠깐 끼어들어도 될까요?)
```

# Week 14: 일상 커뮤니케이션과 글쓰기

## Lesson 35 — 일상 대화와 스몰톡

---

### 1. WHY — 스몰톡은 왜 중요한가

한국에서는 "쓸데없는 잡담"으로 여겨질 수 있는 스몰톡이, 영어권 문화에서는 **관계 구축의 필수 도구**다.

```
스몰톡 = 대화의 워밍업
       = 신뢰 관계(rapport)의 시작점
       = 네트워킹의 기본 기술
```

**스몰톡이 중요한 이유:**

1. **첫인상을 결정한다**: 새 동료, 클라이언트, 면접관과의 첫 만남에서 스몰톡이 분위기를 만든다
2. **관계를 유지한다**: 엘리베이터에서 동료를 만났을 때, 커피를 뽑을 때, 회의 시작 전 — 어색한 침묵 대신 가벼운 대화가 관계를 부드럽게 한다
3. **기회를 만든다**: 네트워킹 이벤트, 컨퍼런스, 회식 등에서 자연스러운 대화가 새로운 기회로 이어진다

한국인이 스몰톡에서 겪는 어려움:

| 어려움 | 원인 | 해결책 |
|---|---|---|
| "무슨 말을 해야 할지 모르겠다" | 주제 레퍼토리 부족 | 5대 안전 주제를 미리 준비 |
| "대화가 금방 끝난다" | 후속 질문 기술 부족 | Follow-up question 패턴 연습 |
| "영어로 말하면 딱딱해진다" | 자연스러운 구어체 표현 부족 | 일상 표현 + 리액션 패턴 습득 |
| "끝내는 타이밍을 모르겠다" | 마무리 표현 부족 | Closing 패턴 3~4개 암기 |

> **핵심 원리**: "스몰톡은 정보 교환이 아니다. 감정 교류다. '무슨 말을 했느냐'보다 '대화가 즐거웠느냐'가 중요하다."

---

### 2. CORE — 스몰톡의 기본 주제와 패턴

#### 5대 안전 주제 (Safe Topics)

어떤 상황에서든 무난하게 꺼낼 수 있는 주제들:

```
1. 날씨 (Weather)         — 가장 보편적인 스몰톡 주제
2. 주말/휴가 계획 (Plans)  — 가벼우면서도 대화를 확장하기 좋다
3. 취미/관심사 (Hobbies)   — 공통점을 찾기 쉽다
4. 음식/맛집 (Food)        — 누구나 관심 있는 주제
5. 여행 (Travel)           — 이야기가 풍부해진다
```

**피해야 할 주제 (Taboo Topics):**
- 정치 (Politics)
- 종교 (Religion)
- 급여/재정 상황 (Salary/Money)
- 나이/외모 (Age/Appearance)
- 논쟁적 시사 이슈 (Controversial issues)

---

#### 인사 패턴 (Greetings)

교과서 "How are you? I'm fine, thank you"는 실전에서 거의 안 쓴다. 자연스러운 인사 패턴:

**격식 수준별:**

| 격식 | 인사 | 적절한 대답 |
|---|---|---|
| 격식 | How do you do? | Pleased to meet you. |
| 보통 | How are you doing? | Pretty good, thanks. How about you? |
| 캐주얼 | How's it going? | Not bad. You? |
| 캐주얼 | What's up? | Not much. Just the usual. |
| 친한 사이 | Hey! What have you been up to? | Oh, you know, the usual. Actually, I just started... |

**자연스러운 대답 패턴:**

```
A: How's it going?
B: Pretty good, thanks! Actually, I just got back from a trip
   to Jeju. (단순 대답 + 화제 제공)

A: How have you been?
B: I've been busy with the new project, but it's going well.
   How about you? (근황 + 되묻기)

A: What have you been up to?
B: Not too much, actually. I've been trying out a new coffee shop
   near the office. Have you been there? (근황 + 질문으로 대화 확장)
```

> **핵심**: 인사에 대한 대답은 **짧은 대답 + 한 가지 정보 추가 + 되묻기**의 3단 구조로 하면 대화가 자연스럽게 이어진다.

---

#### 근황 표현 (Talking About What You've Been Doing)

현재완료 진행형(Phase 4에서 배운 것)이 빛을 발하는 순간이다:

```
I've been working on a new project lately.
(최근에 새 프로젝트 작업을 하고 있어요.)

I've been trying to learn cooking on weekends.
(주말마다 요리를 배워보고 있어요.)

I recently started going to a gym near my apartment.
(최근에 집 근처 헬스장에 다니기 시작했어요.)

I just finished reading a really interesting book.
(정말 재미있는 책을 방금 다 읽었어요.)

I've been getting into hiking these days.
(요즘 등산에 빠져있어요.)
```

---

#### 의견 묻기와 대화 확장 (Asking for Opinions & Expanding)

대화를 이어가는 핵심은 **후속 질문(follow-up question)** 이다:

```
What do you think about the new office layout?
(새 사무실 배치 어떻게 생각해요?)

Have you tried that new restaurant near the station?
(역 근처 새로 생긴 식당 가봤어요?)

Do you have any recommendations for a good podcast?
(좋은 팟캐스트 추천해줄 수 있어요?)

Are you planning anything fun for the long weekend?
(연휴에 재미있는 계획 있어요?)
```

**후속 질문 패턴 (대화를 끊기지 않게 하는 기술):**

```
상대가: "I went to Busan last weekend."

좋은 후속:
→ Oh, really? How was it? (일반적 후속)
→ Nice! What did you do there? (활동 질문)
→ I love Busan! Did you go to Haeundae? (공감 + 구체적 질문)
→ That sounds fun. Was it crowded? (반응 + 상황 질문)

나쁜 후속:
→ Oh. (대화 종료)
→ I see. (관심 없어 보임)
```

> **대화 확장의 원칙**: 상대방이 한 말에서 **키워드를 하나 잡아서** 그것에 대해 질문한다. "Busan" → "Did you go to Haeundae?", "weekend" → "What else did you do?"

---

#### 마무리 표현 (Closing a Conversation)

스몰톡을 자연스럽게 끝내는 것도 중요한 기술이다:

```
자연스러운 마무리:
Well, it was nice talking to you. I should get back to work.
(이야기 즐거웠어요. 다시 일하러 가야겠네요.)

I'd love to chat more, but I have a meeting in five minutes.
(더 이야기하고 싶은데, 5분 후에 회의가 있어요.)

Let's catch up again soon!
(조만간 또 이야기해요!)

It was great seeing you. Enjoy the rest of your day!
(만나서 반가웠어요. 좋은 하루 보내세요!)

Anyway, I'll let you get back to what you were doing. Talk to you later!
(어쨌든, 하시던 일 계속하세요. 나중에 또 이야기해요!)
```

### 3. APPLY — 상황별 대화 예시

#### 예시 1: 커피 브레이크 (Coffee Break)

```
You:    Hey, Sarah! How's your morning going?
Sarah:  Not bad! Just needed some coffee to survive the afternoon.
        How about you?
You:    Same here. I've been staring at spreadsheets all morning.
        By the way, have you tried the new cafe downstairs?
Sarah:  Oh, I haven't! Is it good?
You:    Yeah, their iced latte is really good. You should try it sometime.
Sarah:  I'll definitely check it out. Thanks for the recommendation!
You:    No problem! Well, I'd better get back to my desk.
        Talk to you later!
Sarah:  Sure, see you around!
```

**대화 분석:**
- 가벼운 인사로 시작
- 공감 형성 ("Same here")
- 자연스러운 화제 전환 ("By the way")
- 추천 + 부드러운 마무리

---

#### 예시 2: 점심 시간 (Lunch)

```
You:      Mind if I sit here?
David:    Not at all! Go ahead.
You:      Thanks. So, how's the project going?
David:    It's been intense, but we're making good progress.
          We're hoping to finish the first phase by next week.
You:      That's great to hear. I remember you mentioned
          it was a tight deadline.
David:    Yeah, it still is, but the team's been working really hard.
          What about you? How's your side going?
You:      Pretty well, actually. I've been working on the new feature,
          and I think we'll be ready for testing soon.
David:    Nice! Oh, by the way, did you see the email about
          the team dinner next Friday?
You:      I did! Are you going?
David:    Yeah, I think so. It'll be a good chance to unwind.
You:      Definitely. I'm looking forward to it.
```

**대화 분석:**
- 자리 허락 요청으로 자연스러운 시작
- 업무 관련 가벼운 대화
- "By the way"로 화제 전환
- 공통 관심사(팀 저녁)로 연결

---

#### 예시 3: 엘리베이터 (Elevator — 30초 대화)

```
You:      Good morning! Going to the 12th floor too?
Emily:    Yep! Another Monday, right?
You:      Ha, exactly. Did you have a good weekend?
Emily:    Actually, yes! I went hiking at Bukhansan.
You:      Oh nice! How was the weather up there?
Emily:    It was perfect. Clear skies and not too cold.
You:      Sounds wonderful. I should plan a hike sometime soon.
Emily:    You definitely should! Oh, here's my floor.
          Have a good day!
You:      You too! Enjoy the week.
```

**대화 분석:**
- 30초 안에 자연스러운 인사 → 주말 화제 → 마무리
- 엘리베이터 도착이 자연스러운 종료 지점

---

#### 예시 4: 네트워킹 이벤트 (Networking Event)

```
You:      Hi, I'm James. I work in the product team at ABC Corp.
Stranger: Nice to meet you, James! I'm Lisa. I'm a UX designer
          at XYZ Studio.
You:      Oh, UX design! That's really interesting. How long have
          you been doing that?
Lisa:     About five years now. I actually started as a graphic
          designer and then transitioned into UX.
You:      That's a great career path. What made you switch?
Lisa:     I realized I was more interested in understanding
          user behavior than just making things look pretty.
You:      That makes a lot of sense. We actually just started
          a UX improvement project at our company.
          We should exchange ideas sometime.
Lisa:     I'd love that! Here's my card.
You:      Thanks! It was great meeting you, Lisa.
Lisa:     Likewise! Let's keep in touch.
```

**대화 분석:**
- 자기소개로 시작
- 상대의 직업에 관심 표현
- 이야기 흐름에서 자연스럽게 연결고리 발견
- 구체적 후속 행동 제안 (연락 교환)

## Lesson 36 — 글쓰기와 요약

---

### 1. WHY — 영어 글쓰기의 핵심 원칙

영어 글쓰기에서 좋은 글의 기준은 3C로 요약된다:

```
Clarity      — 명확함 (읽는 사람이 한 번에 이해)
Conciseness  — 간결함 (불필요한 말을 빼기)
Coherence    — 일관성 (논리적 흐름이 자연스러움)
```

한국어 글쓰기와 영어 글쓰기의 결정적 차이:

| 한국어 글쓰기 | 영어 글쓰기 |
|---|---|
| 배경/맥락을 먼저 깐다 | **결론을 먼저** 말한다 |
| 두괄식도 있지만 미괄식이 자연스럽다 | **두괄식(topic sentence first)** 이 기본 |
| 은유, 비유, 우회적 표현을 선호 | 직접적이고 구체적인 표현을 선호 |
| 문장이 길어도 자연스럽다 | 짧은 문장이 좋은 문장이다 |
| 주어 생략이 자연스럽다 | 주어를 반드시 명시한다 |

**나쁜 영어 글쓰기 vs 좋은 영어 글쓰기:**

```
나쁜 예:
Due to the fact that we had a lot of problems with the system that
we were using before, which was causing many issues for the team
members who were trying to complete their work on time, we have
decided to make a change to a new system.

좋은 예:
We switched to a new system because the old one caused frequent delays.
```

> **핵심 원리**: "좋은 영어 글쓰기는 '뺄셈'이다. 읽는 사람의 시간을 존중하여 불필요한 단어를 모두 제거한다."

---

### 간결하게 만드는 구체적 기법

**기법 1: 불필요한 표현 제거**

| 장황한 표현 | 간결한 표현 |
|---|---|
| Due to the fact that | Because |
| In order to | To |
| At this point in time | Now |
| In the event that | If |
| It is important to note that | (삭제하고 바로 본론) |
| For the purpose of | To / For |
| In spite of the fact that | Although / Despite |
| On a weekly basis | Weekly |
| Make a decision | Decide |
| Give consideration to | Consider |

**기법 2: 능동태 사용**

```
수동태: The report was completed by the team.
능동태: The team completed the report.

수동태: A decision was made to postpone the meeting.
능동태: We decided to postpone the meeting.

수동태: It was determined by the committee that changes were needed.
능동태: The committee determined that changes were needed.
```

> **Phase 3 복습**: 수동태가 필요한 경우도 있다 (행위자가 불명확하거나, 행위 자체가 중요할 때). 하지만 기본값은 능동태다.

**기법 3: 구체적으로 쓰기**

```
모호: The project went well.
구체: The project was completed two days ahead of schedule
      and 5% under budget.

모호: We need to improve our process.
구체: We need to reduce the review cycle from five days to three days.

모호: The team did a good job.
구체: The team resolved 95% of customer complaints within 24 hours.
```

---

### 2. CORE — 단락(Paragraph) 구조

영어 글쓰기의 기본 단위는 **단락(paragraph)** 이다. 하나의 단락은 **하나의 아이디어**만 다룬다.

```
┌─────────────────────────────────────────┐
│  Topic Sentence (주제문)                │  ← 이 단락이 말하고자 하는 핵심
│  Supporting Detail 1 (뒷받침 1)         │  ← 근거, 예시, 설명
│  Supporting Detail 2 (뒷받침 2)         │  ← 추가 근거/예시
│  Supporting Detail 3 (뒷받침 3)         │  ← (필요시)
│  Concluding Sentence (마무리문)          │  ← 요약 또는 다음 단락으로 전환
└─────────────────────────────────────────┘
```

**예시:**

```
Remote work has significantly improved employee productivity at our company.
(원격 근무는 우리 회사의 직원 생산성을 크게 향상시켰다.) [Topic Sentence]

According to our internal survey, 78% of employees reported that they
accomplish more tasks when working from home.
(내부 설문에 따르면, 78%의 직원이 재택근무 시 더 많은 업무를 완수한다고 응답했다.)
[Supporting Detail 1 — 데이터]

The main reason is the elimination of commuting time, which gives
employees an extra one to two hours each day.
(주된 이유는 통근 시간이 없어져 직원들이 매일 1~2시간을 추가로 확보하기 때문이다.)
[Supporting Detail 2 — 이유]

Additionally, employees reported fewer interruptions at home compared
to the open office environment.
(또한 직원들은 개방형 사무실 환경에 비해 집에서 방해가 적다고 보고했다.)
[Supporting Detail 3 — 추가 근거]

These findings suggest that a hybrid work model could be the optimal
solution for maintaining both productivity and team collaboration.
(이러한 결과는 하이브리드 근무 모델이 생산성과 팀 협업 모두를 유지하는
최적의 방안일 수 있음을 시사한다.) [Concluding Sentence]
```

---

### 연결어 활용 (Transition Words)

단락과 단락, 문장과 문장을 연결하는 단어들이 글의 논리적 흐름을 만든다:

| 기능 | 연결어 | 예문 |
|---|---|---|
| **추가** | In addition, Furthermore, Moreover, Also | In addition, we need to consider the timeline. |
| **대조** | However, On the other hand, In contrast, Nevertheless | However, the cost may be too high. |
| **원인/결과** | Therefore, As a result, Consequently, Thus | As a result, we decided to change our approach. |
| **예시** | For example, For instance, Such as, Specifically | For example, last quarter's results show a clear trend. |
| **강조** | In fact, Indeed, Notably, Most importantly | In fact, the data contradicts the initial assumption. |
| **요약** | In summary, To conclude, Overall, In short | In summary, three key changes are needed. |
| **순서** | First, Second, Finally, Next, Then | First, we need to gather the data. |
| **양보** | Although, Even though, Despite, While | Although the plan is ambitious, it is achievable. |

**연결어 실전 사용 예시:**

```
The new software significantly reduced processing time.
For example, tasks that used to take three hours can now be completed
in under one hour. As a result, the team has been able to take on
20% more projects this quarter. However, some team members have
reported a steep learning curve. Therefore, we recommend providing
additional training sessions next month.
```

**분석:**
- For example → 구체적 예시 제공
- As a result → 결과 연결
- However → 반대 관점 전환
- Therefore → 결론/제안으로 마무리

---

### 요약 기술 (Summarizing Skills)

요약은 영어 글쓰기의 핵심 기술이다. 회의록, 보고서, 이메일 — 모든 곳에서 필요하다.

**요약의 3단계:**

```
Step 1: Main Idea 파악 — 글의 핵심 주장/메시지가 무엇인가?
Step 2: Key Details 추출 — 핵심을 뒷받침하는 중요한 세부사항은?
Step 3: Paraphrase — 자신의 말로 다시 쓰기 (원문 표현을 그대로 쓰지 않기)
```

**Paraphrasing 기법:**

| 원문 | 패러프레이즈 | 사용 기법 |
|---|---|---|
| The project was completed successfully. | The team finished the project without any issues. | 동의어 교체 + 구조 변경 |
| Sales increased by 30%. | Revenue grew by nearly a third. | 수치 표현 변경 |
| Many employees prefer remote work. | A significant number of staff favor working from home. | 동의어 + 관점 전환 |

**요약 실전 연습 — 원문과 요약:**

원문 (150단어):
```
The company's annual employee satisfaction survey, which was conducted
last month and received responses from over 2,000 employees across
all departments, revealed several important findings. First, 85% of
employees rated their overall job satisfaction as "good" or "excellent,"
which is a 10% improvement from last year. Second, the most commonly
cited reason for high satisfaction was the flexible work arrangement
policy that was introduced six months ago. Third, the areas that
received the lowest scores were career development opportunities and
internal communication between departments. Based on these results,
the HR team has proposed three initiatives: expanding the mentorship
program, creating cross-departmental project teams, and launching
a quarterly town hall meeting series.
```

요약 (50단어):
```
The annual employee survey showed that satisfaction rose to 85%,
mainly due to the flexible work policy. However, career development
and cross-department communication scored low. In response, HR plans
to expand mentorship, form cross-departmental teams, and start
quarterly town halls.
```

**요약에서 유용한 표현:**

```
시작:
The article discusses... / The report highlights... /
According to the survey... / The main argument is that...

핵심 전달:
The key finding is that... / The author argues that... /
The data shows that... / The main point is...

마무리:
In conclusion, the author recommends... /
Overall, the report suggests that... /
To sum up, three main issues were identified.
```

### 3. APPLY — 글쓰기 실전 예시

#### 예시 1: 짧은 의견 글 (Opinion Paragraph)

주제: "Should companies allow employees to work from home permanently?"

```
I believe that companies should offer a hybrid work model rather
than fully remote or fully in-office arrangements. Working from home
increases productivity by eliminating commuting time and reducing
office distractions. For instance, a recent study found that remote
workers completed 13% more tasks than their office-based colleagues.
However, fully remote work can lead to isolation and weaken team
collaboration. Therefore, a hybrid model — where employees work from
home two to three days a week — provides the best of both worlds:
the focus of remote work and the connection of in-person interaction.
```

**구조 분석:**
1. Topic Sentence: 입장 표명 (하이브리드 모델 지지)
2. Supporting Detail 1: 재택근무의 장점 + 데이터
3. Supporting Detail 2: 완전 재택의 단점 (However로 전환)
4. Concluding Sentence: 결론 (Therefore로 마무리)

---

#### 예시 2: 보고서 요약 (Report Summary)

```
Executive Summary

This report examines the effectiveness of the new customer service
training program that was implemented in January 2026.

Key Findings:
- Customer satisfaction scores improved by 22% compared to the
  previous quarter.
- Average response time decreased from 48 hours to 18 hours.
- The number of escalated complaints dropped by 35%.

Recommendations:
Based on these results, we recommend the following actions:
1. Expand the training program to all regional offices by Q3 2026.
2. Develop an advanced module for senior support staff.
3. Conduct a follow-up evaluation in six months to measure
   long-term impact.
```

### 앞으로의 학습 방향

1. **매일 영어 이메일 1통 쓰기**: 실전 상황이 아니더라도, 오늘 있었던 일을 영어 이메일 형식으로 써본다
2. **영어 콘텐츠 소비**: 뉴스, 팟캐스트, 유튜브 등을 영어로 접하며 자연스러운 표현을 흡수한다
3. **영어 일기 쓰기**: 하루 3~5문장으로 오늘의 일을 영어로 기록한다. Topic sentence 연습에 탁월하다
4. **스몰톡 기회 만들기**: 외국인 동료, 온라인 커뮤니티 등에서 가벼운 대화를 시도한다
5. **요약 연습**: 읽은 기사나 본 영상의 내용을 3문장으로 요약하는 습관을 들인다
