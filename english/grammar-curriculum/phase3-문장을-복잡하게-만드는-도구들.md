## Week 6: 조동사 — 동사에 의미를 더하다

> 조동사(Modal Verbs)는 동사 앞에 붙어서 **말하는 사람의 태도**를 표현한다.
> 능력, 가능성, 의무, 허가, 추측 — 이 모든 것이 조동사 하나로 결정된다.

---

### Lesson 16 — 조동사 — 동사에 의미를 더하다

#### 1. WHY — 조동사는 왜 존재하는가?

영어에서 동사는 **"무엇을 하는가"**를 알려준다. 하지만 현실의 대화에서는 단순히 행동만 전달하는 게 아니다.

- "할 수 있다" (능력)
- "할 것이다" (의지)
- "해야 한다" (의무)
- "할지도 모른다" (가능성)

한국어에서는 이런 뉘앙스를 **어미 변화**로 처리한다: "한다 / 할 수 있다 / 해야 한다 / 할지도 모른다."
영어에서는 **동사 앞에 별도의 단어(조동사)**를 놓아서 이 의미를 추가한다.

```
동사만:       I submit this.          (나는 이것을 제출한다)
조동사 추가:  I can submit this.      (나는 이것을 제출할 수 있다)
              I must submit this.     (나는 이것을 제출해야 한다)
              I might submit this.    (나는 이것을 제출할지도 모른다)
```

**핵심 원리**: 동사는 **행동(action)**을 담당하고, 조동사는 그 행동에 대한 **화자의 판단(mode)**을 담당한다.

이것이 바로 "모달(modal)"이라는 이름의 유래다. **Mode(모드)**를 설정하는 동사라는 뜻이다.

#### 2. CORE — 핵심 개념을 가장 짧은 문장으로 체득

조동사의 기본 공식:

```
주어 + 조동사 + 동사원형
```

**절대 규칙**: 조동사 뒤에는 반드시 **동사원형**이 온다. 3인칭 단수 -s도 붙지 않는다.

```
(X) He cans fix it.
(X) She must fixes it.
(O) He can fix it.
(O) She must fix it.
```

각 조동사의 **핵심 한 줄 정의**:

| 조동사 | 핵심 의미 | 최소 문장 |
|--------|-----------|-----------|
| **can** | 능력/가능성 | I can help. |
| **could** | 약한 가능성/공손한 요청 | I could help. |
| **will** | 의지/미래 | I will finish it. |
| **would** | 가정/공손 | I would suggest this. |
| **should** | 권고/당위 | You should check it. |
| **must** | 강한 의무/확신 | We must submit today. |
| **may** | 허가/가능성 | You may proceed. |
| **might** | 약한 가능성 | It might be wrong. |

**부정형**: 조동사 + not

```
I cannot accept this.       (= can't)
You should not skip this step.  (= shouldn't)
We must not ignore the deadline.  (= mustn't)
```

**의문형**: 조동사를 주어 앞으로

```
Can you help me?
Should we check again?
Will the report be ready?
```

#### 3. EXPAND — 짧은 문장에서 복잡한 문장으로

**Step 1: 기본 — 조동사 + 동사원형**

```
I can help.
We should check.
They must submit.
```

**Step 2: 목적어 추가**

```
I can prepare the report.
We should review the documents.
They must submit the tax return.
```

**Step 3: 부사/전치사구 추가**

```
I can prepare the report by tomorrow.
We should review the documents before the meeting.
They must submit the tax return to the office immediately.
```

**Step 4: 조동사 + be + -ing (진행 의미 추가)**

```
He could be working on the report right now.
The client might be waiting for our response.
She should be reviewing the contract by now.
```

**Step 5: 조동사 + have + p.p. (과거 사건에 대한 현재 판단)**

```
He could have finished it yesterday.         (끝낼 수 있었는데 안 했다)
She should have checked the numbers first.   (먼저 숫자를 확인했어야 했다)
The package must have arrived last night.    (어젯밤 택배가 틀림없이 도착했다)
They might have already sent the documents.  (이미 서류를 보냈을 수도 있다)
```

이 구조가 **매우 중요하다**: `조동사 + have + p.p.`는 **과거 사실에 대한 현재 시점의 판단**을 표현한다.

**Step 6: 복합 문장 속 조동사**

```
If the weather is good, we can have the meeting outside.
Although the deadline passed, we should still try to submit.
I think we must finish this project before the holiday.
```

#### 4. DOMAIN — 세무 도메인 실제 예문

**세무 도메인**:

```
Taxpayers must file their returns by March 31.
(납세자는 3월 31일까지 신고해야 한다.)

You can claim a deduction for home office expenses.
(재택근무 비용에 대해 공제를 신청할 수 있습니다.)

This income might be subject to additional tax.
(이 소득은 추가 세금 대상일 수 있습니다.)

The tax authority may impose penalties for late filing.
(세무 당국은 늦은 신고에 대해 과태료를 부과할 수 있습니다.)

We should verify the withholding tax calculation before submission.
(제출 전에 원천징수세 계산을 확인해야 합니다.)

The client could have deducted those expenses last year.
(그 고객은 작년에 그 비용을 공제할 수 있었다. — 하지만 안 했다.)
```

**일반 비즈니스 도메인**:

```
The meeting should finish within 30 minutes.
(회의는 30분 내에 끝나야 합니다.)

We must ensure consistency across all departments.
(모든 부서 간 일관성을 보장해야 합니다.)

The schedule might change under heavy workload.
(높은 업무량 상태에서 일정이 변경될 수 있습니다.)

You can use this template to prepare the monthly report.
(월간 보고서를 준비하기 위해 이 템플릿을 사용할 수 있습니다.)

This plan will cover all major tasks for the quarter.
(이 계획은 분기의 모든 주요 업무를 포함할 것입니다.)

We should have started the preparation earlier.
(준비를 더 일찍 시작했어야 했습니다.)
```

#### 5. PRACTICE — 직접 문장 만들기 연습

**A. 빈칸 채우기: 적절한 조동사를 고르시오**

```
1. You _______ check all the numbers before submitting the report.
   (보고서를 제출하기 전에 반드시 모든 숫자를 확인해야 한다)
   → (a) can  (b) might  (c) must  (d) could

2. If we prepare early, the project _______ finish ahead of schedule.
   (일찍 준비하면 프로젝트가 일정보다 빨리 끝날 수 있을 것이다)
   → (a) must  (b) could  (c) can  (d) should

3. The office _______ be closed. The lights are off.
   (사무실이 닫힌 것 같다. 불이 꺼져 있다)
   → (a) should  (b) might  (c) will  (d) can

4. We _______ have sent the invoice without double-checking.
   (확인 없이 청구서를 보내지 말았어야 했다)
   → (a) should  (b) must  (c) shouldn't  (d) wouldn't
```

**B. 한국어 → 영어 작문**

```
1. 이 양식은 다양한 유형의 소득을 처리할 수 있습니다.
   → _______________________________________________

2. 제출 전에 서류를 검토해야 합니다. (권고)
   → _______________________________________________

3. 서류 전달이 늦어졌을 수도 있습니다.
   → _______________________________________________

4. 그 실수를 어제 고칠 수 있었는데 (안 고쳤다).
   → _______________________________________________
```

**C. 딱딱한 표현을 자연스러운 영어로 바꾸시오**

```
1. "Not possible to meet the deadline"
   → "We _______ meet the deadline."

2. "It is necessary to review the contract"
   → "We _______ review the contract."

3. "It is recommended to keep records for five years"
   → "You _______ keep records for five years."
```

### Lesson 17 — 조동사의 과거형이 "과거"가 아닌 이유

#### 1. WHY — 영어에서 가장 혼란스러운 부분 중 하나

한국인 학습자가 가장 자주 하는 실수 중 하나:

> "could는 can의 과거형이니까, '~할 수 있었다'라는 뜻이겠지?"

**틀렸다.** 정확히 말하면, **절반만 맞다.**

`could`가 **실제 과거**를 의미하는 경우도 있지만, 대부분의 실무 영어에서 `could`는 **현재나 미래의 불확실한 가능성** 또는 **공손한 요청**을 뜻한다.

왜 이런 일이 벌어지는가? 영어에는 **"거리감(distance)"** 이라는 핵심 개념이 있기 때문이다.

```
시간적 거리 (temporal distance)  → 과거
심리적 거리 (psychological distance) → 불확실, 가정
사회적 거리 (social distance)    → 공손함, 격식
```

영어의 과거 시제 형태(-ed, could, would 등)는 이 **세 가지 거리**를 모두 표현할 수 있다. 시간적으로 먼 것(과거), 현실에서 먼 것(가정/불확실), 관계에서 먼 것(공손함) — 모두 같은 형태를 사용한다.

이것이 바로 **영어적 사고방식의 핵심** 중 하나다.

#### 2. CORE — 핵심 개념을 가장 짧은 문장으로 체득

**can vs could**:

```
I can fix it.    → 나 고칠 수 있어. (현재 능력, 확신)
I could fix it.  → 나 고칠 수도 있어. (가능성, 불확실) / 고쳐줄 수 있는데요. (공손)
```

**will vs would**:

```
I will do it.    → 나 할 거야. (확실한 의지/미래)
I would do it.   → 나라면 할 텐데. (가정) / 하겠습니다. (공손)
```

**핵심 정리표: 현재형 vs 과거형 조동사**

| 현재형 | 의미 | 과거형 | 의미 변화 |
|--------|------|--------|-----------|
| can | 할 수 있다 (확신) | could | 할 수도 있다 (약한 가능성) / 공손 |
| will | 할 것이다 (확신) | would | 할 텐데 (가정) / 공손 |
| shall | ~하겠다 | should | ~해야 한다 (권고) |
| may | 해도 된다 / 일 수 있다 | might | 일 수도 있다 (더 약한 가능성) |

**`shall → should` 변화가 특히 재미있다**: shall은 원래 "~하겠다"인데, 과거형 should는 "~해야 한다(권고)"로 의미가 완전히 달라졌다. 거리감이 생기면서 "직접적 의지" → "한 발 물러선 조언"이 된 것이다.

#### 3. EXPAND — 짧은 문장에서 복잡한 문장으로

**Pattern 1: could = 약한 가능성 (현재/미래)**

```
The plan could fail.
(계획이 실패할 수도 있다 — 확실하지 않지만 가능성 있음)

This approach could reduce costs by 40%.
(이 접근법은 비용을 40% 줄일 수도 있다)

We could move to the new office next quarter.
(다음 분기에 새 사무실로 이전할 수도 있다)
```

**Pattern 2: could = 공손한 요청**

```
Could you check my report?
(제 보고서를 확인해 주실 수 있을까요?)

Could you explain the tax calculation method?
(세금 계산 방법을 설명해 주실 수 있을까요?)
```

비교:
```
Can you help me?    → (직접적) 이거 도와줄 수 있어?
Could you help me?  → (공손하게) 도와주실 수 있을까요?
```

**Pattern 3: would = 가정 상황**

```
I would change this, but we don't have time.
(나라면 이걸 바꾸겠지만, 시간이 없다)

That would cause a bigger problem.
(그러면 더 큰 문제가 생길 것이다 — 만약 그렇게 한다면)

If we had more staff, we would finish on time.
(직원이 더 있었다면, 제때 끝낼 텐데)
```

**Pattern 4: would = 공손한 제안/요청**

```
I would suggest reviewing the contract first.
(먼저 계약서를 검토하는 것을 제안드립니다)

Would you like me to prepare the meeting agenda?
(회의 안건을 준비해 드릴까요?)

I would appreciate it if you could send the documents by Friday.
(금요일까지 서류를 보내주시면 감사하겠습니다)
```

**Pattern 5: 확실성의 스펙트럼**

영어에서 조동사는 **확실성의 단계**를 표현한다:

```
확실 ←――――――――――――――――――――――――→ 불확실

must be   will be   should be   can be   could be   may be   might be
틀림없다   ~일 것    ~일 것이다    ~일 수    ~일 수도    ~일 수    ~일지도
          (확신)    (예상)       있다      있다       있다      모르다
```

```
The answer must be wrong.      (틀림없이 틀렸다 — 99%)
The answer will be ready.      (준비될 거다 — 95%)
The answer should be correct.  (맞을 거다 — 80%)
The answer could be different. (다를 수도 있다 — 50%)
The answer may be surprising.  (놀라울 수 있다 — 40%)
The answer might be wrong.     (틀릴지도 모른다 — 20%)
```

#### 4. DOMAIN — 세무 도메인 실제 예문

**세무 도메인 — 공손한 고객 응대**:

```
직접적 (부자연스러움):
"Can you send your tax documents?"

공손한 (자연스러움):
"Could you send your tax documents by next Friday?"
(금요일까지 세무 서류를 보내주실 수 있을까요?)

더 공손한:
"Would you be able to send your tax documents at your earliest convenience?"
(편하실 때 세무 서류를 보내주실 수 있으시겠습니까?)
```

**세무 도메인 — 가능성 표현**:

```
The taxpayer could qualify for a small business deduction.
(그 납세자는 소기업 공제 자격이 될 수도 있습니다.)

This income would be taxable if the exemption doesn't apply.
(면제가 적용되지 않으면 이 소득은 과세 대상이 될 것입니다.)

The penalty might be waived if the taxpayer files an appeal.
(납세자가 이의를 제기하면 과태료가 면제될 수도 있습니다.)
```

**일반 비즈니스 도메인 — 업무 소통에서의 공손 표현**:

```
"Could you review this report by tomorrow?"
(내일까지 이 보고서를 검토해 주실 수 있을까요?)

"I would recommend starting the preparation earlier."
(준비를 더 일찍 시작하는 것을 추천드리겠습니다.)

"Would it make sense to schedule a follow-up meeting?"
(후속 회의를 잡는 것이 합리적일까요? — 공손한 제안)

"This plan would not work if the budget is reduced."
(예산이 줄어들면 이 계획은 효과가 없을 것입니다 — 가정 상황)
```

#### 5. PRACTICE — 직접 문장 만들기 연습

**A. can vs could — 적절한 것을 고르시오**

```
1. _______ you help me with this task?
   (이 업무 좀 도와줄 수 있어? — 동료에게 편하게)
   → can / could

2. _______ you review this document when you have a moment?
   (시간 되실 때 이 서류 검토해 주실 수 있을까요? — 상사에게 공손하게)
   → can / could

3. This method _______ reduce our expenses by 30%.
   (이 방법이 비용을 30% 줄일 수도 있다 — 불확실)
   → can / could

4. Our team _______ handle this project alone.
   (우리 팀은 이 프로젝트를 단독으로 처리할 수 있다 — 확신)
   → can / could
```

**B. will vs would — 적절한 것을 고르시오**

```
1. If we hire more staff, the workload _______ decrease.
   → will / would

2. I _______ finish the report tonight.
   (오늘 밤에 보고서를 끝낼 거야 — 확실한 의지)
   → will / would

3. I _______ recommend discussing this with the manager first.
   (먼저 매니저와 상의하는 것을 추천드리겠습니다 — 공손)
   → will / would

4. _______ you like me to explain the process?
   (절차를 설명해 드릴까요? — 공손한 제안)
   → Will / Would
```

**C. 확실성 단계별 작문: 같은 상황을 다른 조동사로 표현하시오**

```
상황: "회의가 연기되었다. 이유를 추측하라."

확신 100%: The schedule _______ have changed.
확신 80%:  The schedule _______ have changed.
확신 50%:  The schedule _______ have changed.
확신 20%:  The schedule _______ have changed.
```

**B.** 1-would (가정), 2-will (확실한 의지), 3-would (공손), 4-Would (공손한 제안)

## Week 7: 관계대명사 — 두 문장을 하나로 합치기

> 관계대명사(Relative Pronouns)는 **두 개의 독립적인 문장을 하나로 결합**하는 도구다.
> 접착제처럼 두 문장을 붙여서, 반복을 줄이고 더 자연스러운 하나의 문장으로 만든다.

---

### Lesson 18 — 관계대명사가 존재하는 이유

#### 1. WHY — 왜 두 문장을 합쳐야 하는가?

다음 두 문장을 보자:

```
I hired an accountant. The accountant knows tax law well.
(나는 회계사를 고용했다. 그 회계사는 세법을 잘 안다.)
```

이렇게 두 문장으로 쓰면 **유치하고 반복적**이다. "accountant"가 두 번 나온다. 한국어에서도 마찬가지다:

```
나는 회계사를 고용했다. 그 회계사는 세법을 잘 안다.
→ 나는 세법을 잘 아는 회계사를 고용했다.
```

한국어는 **관형절(~는, ~은, ~하는)**을 명사 앞에 놓아서 결합한다.
영어는 **관계대명사(who, which, that)**를 사용해서 명사 뒤에 설명을 붙인다.

```
I hired an accountant who knows tax law well.
```

**핵심 차이**: 한국어는 꾸미는 말이 명사 **앞**에, 영어는 명사 **뒤**에 온다.

```
한국어: [세법을 잘 아는] + 회계사       ← 수식어가 앞
영어:   an accountant + [who knows tax law well]  ← 수식어가 뒤
```

이 **어순의 차이**가 한국인 영어 학습자가 관계대명사를 어려워하는 가장 큰 이유다.

#### 2. CORE — 핵심 개념을 가장 짧은 문장으로 체득

**관계대명사의 종류와 역할:**

| 관계대명사 | 선행사 | 역할 | 예문 |
|-----------|--------|------|------|
| **who** | 사람 | 주어 | The person **who** prepared this report... |
| **whom** | 사람 | 목적어 | The accountant **whom** I hired... |
| **which** | 사물 | 주어/목적어 | The error **which** caused the problem... |
| **that** | 사람/사물 | 주어/목적어 | The document **that** we submitted... |
| **whose** | 사람/사물 | 소유 | The team **whose** work was excellent... |

**관계대명사 문장 만들기 공식:**

```
Step 1: 두 문장에서 공통 요소를 찾는다.
  → I met an accountant. + The accountant prepared our tax return.
  → 공통: "accountant"

Step 2: 두 번째 문장의 공통 요소를 관계대명사로 바꾼다.
  → The accountant → who

Step 3: 관계대명사를 선행사 바로 뒤에 놓는다.
  → I met an accountant who prepared our tax return.
```

**최소 문장으로 연습:**

```
I have a colleague. + The colleague speaks English fluently.
→ I have a colleague who speaks English fluently.

I found a mistake. + The mistake changed the total amount.
→ I found a mistake that changed the total amount.

I know a company. + The company's growth has been impressive.
→ I know a company whose growth has been impressive.
```

#### 3. EXPAND — 짧은 문장에서 복잡한 문장으로

**Step 1: 기본 — who/which/that**

```
The accountant who prepared the return is on our team.
The document which contains the financial data is ready.
The form that we use for tax filing is Form 110.
```

**Step 2: 목적격 관계대명사 (생략 가능)**

관계대명사가 **목적어** 역할을 할 때는 생략할 수 있다:

```
The accountant (whom/that) I hired is talented.
                ↑ 생략 가능
→ The accountant I hired is talented.

The method (which/that) we chose is effective.
                  ↑ 생략 가능
→ The method we chose is effective.
```

**주어 역할일 때는 생략 불가:**

```
The accountant who prepared the return... (O)
The accountant prepared the return...     (X) ← 주어가 둘이 되어 문장이 깨진다
```

**Step 3: whose — 소유 관계 표현**

```
I work with a manager. + The manager's experience is extensive.
→ I work with a manager whose experience is extensive.

We visited a company. + The company's reputation is excellent.
→ We visited a company whose reputation is excellent.
```

**Step 4: 전치사 + 관계대명사**

```
This is the project. + I worked on the project.
→ This is the project on which I worked.  (격식)
→ This is the project which I worked on.  (일반)
→ This is the project I worked on.        (구어, 관계대명사 생략)

She is the manager. + I report to the manager.
→ She is the manager to whom I report.    (격식)
→ She is the manager I report to.         (구어)
```

**Step 5: 긴 관계절 — 실무에서 흔한 형태**

```
The tax regulation that the government introduced in January 2025,
which affects all businesses with annual revenue over 500 million won,
requires additional documentation for overseas transactions.
(정부가 2025년 1월에 도입한 세금 규정은 — 연매출 5억 원 이상의 모든
사업체에 영향을 미치는 — 해외 거래에 대한 추가 문서를 요구한다.)

The accountant who handles our corporate tax returns and communicates
with the National Tax Service has been on leave since last week.
(우리 법인세 신고를 처리하고 국세청과 소통하는 회계사가
지난주부터 휴가 중이다.)
```

#### 4. DOMAIN — 세무 도메인 실제 예문

**세무 도메인:**

```
The taxpayer who filed late will receive a penalty notice.
(늦게 신고한 납세자는 과태료 통지를 받을 것이다.)

Expenses that exceed 10 million won must be reported separately.
(1,000만 원을 초과하는 비용은 별도로 신고해야 한다.)

The deduction whose eligibility criteria changed in 2025 affects
small business owners.
(2025년에 자격 기준이 변경된 공제는 소상공인에게 영향을 미친다.)

The tax return that we submitted last week is under review.
(지난주에 제출한 세금 신고서가 검토 중이다.)

The accountant whom the client requested is currently unavailable.
(고객이 요청한 회계사는 현재 부재 중이다.)
```

**일반 비즈니스 도메인:**

```
The manager who oversees the finance department retired last month.
(재무부를 총괄하는 매니저가 지난달 퇴직했다.)

The contract which we signed last year expires in December.
(작년에 서명한 계약이 12월에 만료된다.)

The intern whose presentation impressed everyone got a full-time offer.
(발표로 모두를 감동시킨 인턴이 정규직 제안을 받았다.)

The supplier that we depend on for raw materials raised their prices.
(원자재를 의존하는 공급업체가 가격을 인상했다.)

The new policy, which applies to all employees,
requires mandatory training every quarter.
(모든 직원에게 적용되는 새 정책은 매 분기 의무 교육을 요구한다.)
```

#### 5. PRACTICE — 직접 문장 만들기 연습

**A. 두 문장을 관계대명사로 합치시오**

```

```

### Lesson 19 — 관계부사와 관계대명사의 차이

#### 1. WHY — 관계부사는 왜 따로 존재하는가?

관계대명사는 **명사**를 대체한다 (who = the accountant, which = the error).
하지만 때로는 **장소, 시간, 이유** 같은 부사적 정보를 연결해야 할 때가 있다.

```
I remember the day. + I started working on that day.
→ I remember the day when I started working.
```

여기서 "on that day"는 **부사구(시간 부사)**다. 명사가 아니라 **전치사 + 명사** 덩어리다. 이런 경우에 `when`, `where`, `why`라는 **관계부사**를 사용한다.

**핵심 공식:**

```
관계부사 = 전치사 + 관계대명사

where = in/at which   (장소)
when  = at/on/in which (시간)
why   = for which      (이유)
```

그래서 관계부사는 관계대명사의 **축약형/편의 기능**이라고 볼 수 있다.

#### 2. CORE — 핵심 개념을 가장 짧은 문장으로 체득

**where — 장소:**

```
This is the office. + I work in the office.
→ This is the office where I work.
= This is the office in which I work. (격식)
```

**when — 시간:**

```
I remember the day. + The new policy started on that day.
→ I remember the day when the new policy started.
= I remember the day on which the new policy started. (격식)
```

**why — 이유:**

```
Tell me the reason. + You chose this method for that reason.
→ Tell me the reason why you chose this method.
= Tell me the reason for which you chose this method. (격식)
```

**how — 방법 (특이 케이스):**

```
Show me how you solved the problem.
```

주의: `how`는 선행사를 갖지 않는다. `the way how`는 틀린 표현이다.

```
(X) This is the way how I did it.
(O) This is the way I did it.
(O) This is how I did it.
```

`the way`와 `how`는 동시에 쓸 수 없다 — 둘 중 하나만 선택해야 한다.

#### 3. EXPAND — 짧은 문장에서 복잡한 문장으로

**Step 1: 기본 관계부사**

```
This is where we submit the reports.   (여기가 우리가 보고서를 제출하는 곳이다)
That was when the problem occurred.     (그때 문제가 발생했다)
This is why we use this method.         (이것이 우리가 이 방법을 사용하는 이유다)
```

**Step 2: 선행사 + 관계부사**

```
The office where our team works is on the third floor.
The moment when the announcement was made was very tense.
The reason why we changed the process was efficiency.
```

**Step 3: 관계부사 vs 관계대명사 — 구분법**

```
This is the office where I work.
     → "work"는 완전한 자동사. 목적어 없음. → where (부사)

This is the office which I designed.
     → "designed"는 타동사. "which"가 목적어 역할. → which (대명사)
```

**판별 기준: 관계절이 완전한 문장인가?**

```
관계부사 뒤: 완전한 문장 (주어+동사+목적어 다 있음)
  → The city where I live is Seoul.   ("I live"는 완전)

관계대명사 뒤: 불완전한 문장 (주어 또는 목적어가 빠짐)
  → The city which I visited is Seoul. ("I visited ___" — 목적어 빠짐)
```

**Step 4: 복합 문장에서 관계부사 활용**

```
We need to find the exact point where the mistake was made,
which is likely in the calculation step.
(실수가 발생한 정확한 지점을 찾아야 하는데,
그것은 계산 단계에 있을 가능성이 높다.)

The quarter when we adopted the new tax system was Q3 2025,
and that was also when we hired three new accountants.
(새 세금 시스템을 도입한 분기는 2025년 3분기였고,
그때 회계사 세 명을 채용하기도 했다.)
```

#### 4. DOMAIN — 세무 도메인 실제 예문

**세무 도메인:**

```
The fiscal year when the new tax law takes effect is 2026.
(새 세법이 시행되는 회계연도는 2026년이다.)

This is the form where you report your overseas income.
(이것이 해외 소득을 신고하는 양식이다.)

The reason why the deduction was denied is insufficient documentation.
(공제가 거부된 이유는 불충분한 서류 때문이다.)

Can you explain how the withholding tax is calculated?
(원천징수세가 어떻게 계산되는지 설명해 주시겠습니까?)

The office where taxpayers submit their returns is on the second floor.
(납세자가 신고서를 제출하는 사무실은 2층에 있다.)
```

**일반 비즈니스 도메인:**

```
The conference room where we hold weekly meetings is being renovated.
(주간 회의를 하는 회의실이 리모델링 중이다.)

The period when we receive the most client inquiries is March to May.
(고객 문의가 가장 많은 시기는 3월부터 5월이다.)

This is why we revised our workflow last year.
(이것이 우리가 작년에 업무 흐름을 개선한 이유다.)

Let me show you how the new filing system works.
(새로운 서류 정리 시스템이 어떻게 작동하는지 보여드리겠습니다.)
```

#### 5. PRACTICE — 직접 문장 만들기 연습

**A. where, when, why, how 중 적절한 것을 고르시오**

```
1. This is the office _______ we keep all the tax records.
   → where / when / why / how

2. I don't know _______ the deadline was extended.
   → where / when / why / how

3. The time _______ the filing period begins is January 1st.
   → where / when / why / how

4. Show me _______ you organized the client files.
   → where / when / why / how
```

**B. 관계부사 vs 관계대명사 — 적절한 것을 고르시오**

```
1. The office _______ handles our tax returns is downtown.
   → where / which

2. The office _______ the meeting was held is downtown.
   → where / which

3. The day _______ we submitted the report was a Friday.
   → when / which

4. The day _______ I will never forget was the grand opening.
   → when / which
```

**C. 한국어 → 영어 작문**

```
1. 이것이 우리가 이 절차를 선택한 이유다.
   → __________________________________________________

2. 세금 신고서를 제출하는 웹사이트가 점검 중이다.
   → __________________________________________________

3. 문제가 발생한 시간은 새벽 3시였다.
   → __________________________________________________
```

<details>
<summary>정답 확인</summary>

**A.** 1-where, 2-why, 3-when, 4-how

**B.** 1-which (주격: "handles"의 주어), 2-where (부사: "the meeting was held"는 완전한 문장), 3-when (시간 부사), 4-which (목적격: "I will never forget ___")

**C.**
1. This is why we chose this procedure.
2. The website where you submit tax returns is under maintenance.
3. The time when the problem occurred was 3 AM.

</details>

### Lesson 20 — 제한적 용법 vs 계속적 용법 (콤마의 유무)

#### 1. WHY — 콤마 하나가 의미를 바꾼다

영어에서 관계대명사 앞에 **콤마(,)가 있느냐 없느냐**에 따라 문장의 의미가 완전히 달라진다. 이것은 단순한 문법 규칙이 아니라, **정보의 중요도**를 결정하는 장치다.

```
(A) The employee who finished the report got promoted.
    (그 보고서를 끝낸 직원이 승진했다.)

(B) Mr. Kim, who finished the report, got promoted.
    (김 씨가 — 그가 그 보고서를 끝냈는데 — 승진했다.)
```

**(A)** 에서 "who finished the report"는 **필수 정보**다. 이 정보가 없으면 **어떤 직원**인지 알 수 없다. 여러 직원 중에서 "보고서를 끝낸 그 직원"을 **특정(제한)**하는 역할이다.

**(B)** 에서 "who finished the report"는 **부가 정보**다. "Mr. Kim"이라는 이름만으로 이미 누군지 알 수 있다. 관계절은 그냥 **추가 설명**을 덧붙이는 것이다.

| | 제한적 용법 | 계속적 용법 |
|---|---|---|
| 콤마 | 없음 | 있음 |
| 정보 성격 | 필수 (이것이 없으면 누구/무엇인지 모름) | 부가 (없어도 대상이 명확) |
| 삭제 가능? | 삭제하면 의미 변화 | 삭제해도 핵심 의미 유지 |
| that 사용 | 가능 | **불가능** (콤마 뒤에 that은 안 됨) |

#### 2. CORE — 핵심 개념을 가장 짧은 문장으로 체득

**제한적 용법 (Restrictive) — 콤마 없음:**

```
The employees who work remotely need VPN access.
(원격 근무하는 직원들은 VPN 접근이 필요하다.)
→ 모든 직원이 아니라, "원격 근무하는" 직원만 해당
→ "who work remotely"를 삭제하면: 모든 직원이 VPN이 필요하다는 의미로 변함
```

**계속적 용법 (Non-restrictive) — 콤마 있음:**

```
Our team leader, who has 20 years of experience, approved the plan.
(우리 팀장은 — 20년 경력의 — 그 계획을 승인했다.)
→ 팀장은 한 명. "who has 20 years of experience"는 부가 정보.
→ 삭제해도 문장 의미 동일: "Our team leader approved the plan."
```

**that vs which 규칙:**

```
제한적: that 또는 which 사용 가능 (미국식은 that 선호)
  → The document that/which contains the tax data...

계속적: which만 사용 가능 (that 불가)
  → Our main document, which contains the tax data, ...
  → Our main document, that contains the tax data, ... (X) ← 틀림!
```

#### 3. EXPAND — 짧은 문장에서 복잡한 문장으로

**콤마 유무에 따른 의미 차이 비교:**

```
(A) The branches that are in Seoul handle Korean clients.
    (서울에 있는 지점들이 한국 고객을 담당한다.)
    → 서울에 있는 지점만. 다른 곳 지점은 해당 안 됨.

(B) Our branches, which are in Seoul, handle Korean clients.
    (우리 지점들은 — 서울에 있는 — 한국 고객을 담당한다.)
    → 우리 지점 전부가 서울에 있고, 한국 고객을 담당한다.
```

**계속적 용법의 확장 패턴:**

```
Pattern 1: 고유명사 + , who/which ...
  → Samsung, which is Korea's largest conglomerate, has offices worldwide.
  → Mr. Park, who joined our team last month, already closed two deals.

Pattern 2: 유일한 대상 + , who/which ...
  → My laptop, which has 16GB RAM, runs all the software I need.
  → The CEO, who founded the company in 2015, announced the expansion.

Pattern 3: 절 전체를 받는 which
  → The project succeeded, which surprised everyone.
    (프로젝트가 성공했는데, 그것이 모두를 놀라게 했다.)
  → 여기서 which는 "The project succeeded"라는 사실 전체를 가리킨다.

  → He skipped the review process, which caused a serious error.
    (그는 검토 과정을 건너뛰었는데, 그것이 심각한 실수를 야기했다.)
```

**제한적 용법으로 정교하게 대상 특정하기:**

```
The tax returns that were filed after the deadline will incur penalties.
(마감일 이후에 제출된 세금 신고서는 과태료가 부과될 것이다.)
→ "마감일 이후에 제출된 것만" — 나머지는 해당 없음

The invoices that lack proper documentation need immediate attention.
(적절한 증빙이 없는 청구서들은 즉시 주의가 필요하다.)
→ "증빙이 없는 청구서만" — 나머지는 해당 없음

The clients that require bilingual service are listed in this file.
(이중 언어 서비스가 필요한 고객들이 이 파일에 나열되어 있다.)
→ "이중 언어 서비스가 필요한 고객만" — 나머지는 제외
```

#### 4. DOMAIN — 세무 도메인 실제 예문

**세무 도메인:**

```
제한적:
Taxpayers who earn more than 50 million won must file a comprehensive
income tax return.
(5,000만 원 이상을 버는 납세자는 종합소득세 신고를 해야 한다.)
→ "5,000만 원 이상 버는" 납세자만 해당

계속적:
The National Tax Service, which oversees all tax collection in Korea,
announced new guidelines for digital asset taxation.
(국세청은 — 한국의 모든 세금 징수를 관할하는 — 디지털 자산 과세에 대한
새로운 지침을 발표했다.)
→ 국세청은 하나. 관계절은 부가 설명.

절 전체를 받는 which:
The client missed the filing deadline, which resulted in a 20% penalty.
(고객이 신고 기한을 놓쳤고, 그 결과 20% 과태료가 부과되었다.)
```

**일반 비즈니스 도메인:**

```
제한적:
The departments that handle confidential data require additional security training.
(기밀 데이터를 다루는 부서는 추가 보안 교육이 필요하다.)
→ "기밀 데이터를 다루는" 부서만 해당

계속적:
Our headquarters, which is located in Gangnam, was renovated last year.
(우리 본사는 — 강남에 위치한 — 작년에 리모델링되었다.)
→ 본사는 하나. 관계절은 부가 설명.

절 전체를 받는 which:
We finished the project ahead of schedule, which saved the company
a significant amount of money.
(프로젝트를 일정보다 일찍 끝냈고, 그 결과 회사의 비용이 상당히 절감되었다.)
```

#### 5. PRACTICE — 직접 문장 만들기 연습

**A. 제한적 vs 계속적 — 콤마가 필요한 곳에 콤마를 추가하시오**

```
1. The National Tax Service which is the main tax authority in Korea
   announced new regulations.
   → __________________________________________________

2. The documents that require signatures are on your desk.
   → __________________________________________________

3. Our team lead who has a tax accounting background designed
   the new workflow.
   → __________________________________________________

4. The clients that have annual income above 100 million won
   need extra attention.
   → __________________________________________________
```

**B. that vs which — 적절한 것을 고르시오**

```
1. The form _______ we use for income reporting is Form 110.
   → that / which (둘 다 가능)

2. Form 110, _______ was revised last year, now includes
   a section for overseas income.
   → that / which

3. The error _______ caused the wrong calculation has been corrected.
   → that / which (둘 다 가능)

4. We corrected the calculation error, _______ improved the
   accuracy of the final report by 15%.
   → that / which
```

**C. 한국어 → 영어 작문 (제한적/계속적 구분)**

```
1. 승인이 필요한 서류는 매니저 책상 위에 있다. (제한적)
   → __________________________________________________

2. 우리의 주 거래처인 ABC회사가 가격 인상을 통보했다. (계속적)
   → __________________________________________________

3. 그가 검토를 건너뛰었고, 그 결과 심각한 실수가 발생했다. (절 전체 수식)
   → __________________________________________________
```

## Week 8: 접속사와 복문 — 문장의 흐름 만들기

> 접속사(Conjunctions)는 문장과 문장을 연결하여 **논리적 흐름**을 만든다.
> 나열, 대조, 조건, 이유 등 — 생각과 생각 사이의 관계를 표현하는 영어의 핵심 도구다.

---

### Lesson 21 — 등위접속사: AND, OR, BUT

#### 1. WHY — 문장을 연결하는 가장 기본적인 방법

지금까지 우리는 하나의 문장 안에서 문법을 다뤘다. 하지만 실제 의사소통에서는 **여러 생각을 연결**해야 한다.

```
I prepared the report.     (나는 보고서를 준비했다)
It was approved right away. (바로 승인되었다)
```

이 두 문장의 **관계**가 무엇인가? 나열? 대조? 결과? 이 관계를 표현하는 도구가 **접속사(Conjunction)**다.

가장 기본적인 접속사는 **등위접속사(Coordinating Conjunctions)**로, 두 개의 **대등한** 요소를 연결한다. 영어에서는 **FANBOYS**라는 약자로 7개를 외운다:

```
F - For    (이유: ~이니까)
A - And    (나열: 그리고)
N - Nor    (부정 나열: ~도 아니고)
B - But    (대조: 하지만)
O - Or     (선택: 또는)
Y - Yet    (대조: 그럼에도)
S - So     (결과: 그래서)
```

이 중 실무에서 가장 많이 쓰는 것은 **and, or, but** 세 가지다.

#### 2. CORE — 핵심 개념을 가장 짧은 문장으로 체득

**and = 나열, 추가**

```
I prepared the report and submitted it.
→ 두 행동을 모두 했다.
```

**or = 선택, 대안**

```
Fix it now or do it tomorrow.
→ 둘 중 하나를 해라.
```

**but = 대조, 예외**

```
I finished the task, but it took longer than expected.
→ 업무는 끝냈는데, 예상보다 오래 걸렸다.
```

**등위접속사의 문법 규칙:**

1. 두 개의 **완전한 절(독립절)**을 연결할 때는 **콤마 + 접속사**를 쓴다:
   ```
   I prepared the report, and it was approved right away.
   ```

2. 단어나 구를 연결할 때는 콤마 없이:
   ```
   I like coffee and tea.            (단어 나열)
   She works quickly and efficiently.  (부사 나열)
   ```

3. 세 개 이상 나열할 때는 **Oxford comma** 사용:
   ```
   We need pens, notebooks, and folders.
   (마지막 항목 전에 콤마 + and)
   ```

#### 3. EXPAND — 짧은 문장에서 복잡한 문장으로

**and의 확장:**

```
Level 1: 단어 연결
  → income and expenses

Level 2: 구(phrase) 연결
  → preparing reports and meeting clients

Level 3: 절(clause) 연결
  → I prepared the report, and my colleague reviewed it.

Level 4: 연속 동작 (순서)
  → I gathered the data, organized the spreadsheet, and sent the email.

Level 5: 복합 문장
  → The accounting team reviewed the financial statements and
    prepared the tax returns, and the legal team checked the
    contracts and updated the compliance records.
```

**or의 확장:**

```
Level 1: 단순 선택
  → Pay by card or by bank transfer.

Level 2: 제안/대안 제시
  → We can extend the deadline, or we can request additional help.

Level 3: 경고/위협 (명령문 + or)
  → Submit the documents now, or you will face a penalty.
  → Pay the invoice on time, or we'll charge interest.

Level 4: 불확실성 표현
  → The issue is in the calculation or in the input data.
  → It could take two days or two weeks, depending on the complexity.
```

**but의 확장:**

```
Level 1: 단순 대조
  → It's done, but it needs checking.

Level 2: 양보 + 반전
  → The report is thorough, but the format needs improvement.

Level 3: 기대와 현실의 차이
  → We expected the project to take one month, but it took three months.

Level 4: 부분 긍정/부정
  → The revenue increased, but profit margins decreased.
  → Not the report itself, but the way it was presented needs fixing.
```

**yet의 활용 (but과 비슷하지만 더 강한 대조):**

```
The proposal met all the requirements, yet it was rejected.
(제안서가 모든 요건을 충족했음에도 불구하고, 거절되었다.)

She's a junior staff member, yet her work quality is exceptional.
(주니어 직원인데도, 업무 품질이 뛰어나다.)
```

**so의 활용 (결과):**

```
The storage room was full, so we had to archive old files.
(서류 보관실이 가득 찼고, 그래서 오래된 파일을 보관 처리해야 했다.)

The client's request was urgent, so we prioritized it immediately.
(고객의 요청이 급했기 때문에 즉시 우선순위로 처리했다.)
```

#### 4. DOMAIN — 세무 도메인 실제 예문

**세무 도메인:**

```
and (나열):
The taxpayer must report all domestic and overseas income.
(납세자는 모든 국내 및 해외 소득을 신고해야 한다.)

Prepare the income statement, calculate the tax liability,
and submit the return before the deadline.
(손익계산서를 준비하고, 세금 부채를 계산하고, 마감일 전에 신고서를 제출하라.)

or (선택/경고):
File your return on time, or you will face penalties.
(제때 신고하시오, 그렇지 않으면 과태료에 직면할 것입니다.)

You can claim the standard deduction or itemize your deductions.
(표준 공제를 신청하거나 항목별 공제를 할 수 있습니다.)

but (대조):
The client earned significant income this year, but most of it
qualifies for tax exemptions.
(고객이 올해 상당한 소득을 올렸지만, 대부분 세금 면제 대상이다.)

so (결과):
The tax law changed in 2025, so we need to update our procedures.
(2025년에 세법이 바뀌었으므로 절차를 업데이트해야 한다.)
```

**일반 비즈니스 도메인:**

```
and:
We reviewed the proposal and approved the budget for Q3.
(제안서를 검토하고 3분기 예산을 승인했다.)

or:
Use the standard template or create a custom format for the presentation.
(프레젠테이션에 표준 템플릿을 사용하거나 맞춤 형식을 만들어라.)

but:
The quarterly report was submitted on time, but the figures
need to be double-checked.
(분기 보고서가 제때 제출되었지만, 수치를 재확인해야 한다.)

so:
The client requested a rush order, so we rearranged the schedule.
(고객이 긴급 주문을 요청해서 일정을 재조정했다.)

yet:
We followed all the guidelines, yet the application was still rejected.
(모든 지침을 따랐는데도 신청이 거절되었다.)
```

#### 5. PRACTICE — 직접 문장 만들기 연습

### Lesson 22 — 종속접속사: if, when, because, although

#### 1. WHY — 등위접속사만으로는 부족하다

등위접속사는 두 절을 **대등하게** 연결한다. 하지만 실제 논리에서는 **종속 관계**가 필요하다:

```
대등: 서류를 준비한다 + 고객을 만난다
     → I prepare the documents, and I meet the client. (둘 다 동등한 행동)

종속: 만약 서류가 준비되면 → 고객을 만난다
     → If the documents are ready, I meet the client. (조건 → 결과)
```

**종속접속사(Subordinating Conjunctions)**는 하나의 절을 다른 절에 **의존하게** 만든다. 종속절(부사절)은 혼자서는 완전한 문장이 되지 못한다:

```
"If the documents are ready" ← 이것만으로는 문장이 안 됨. 뭘 어쩌라는 거?
"If the documents are ready, I meet the client." ← 주절과 합쳐져야 완성.
```

#### 2. CORE — 핵심 개념을 가장 짧은 문장으로 체득

**주요 종속접속사와 의미:**

| 접속사 | 의미 | 쉬운 설명 |
|--------|------|-----------|
| **if** | ~하면 | 조건 |
| **unless** | ~하지 않으면 | 부정 조건 (= if not) |
| **when** | ~할 때 | 시점/때 |
| **while** | ~하는 동안 | 동시 진행 |
| **before** | ~하기 전에 | 순서 (먼저) |
| **after** | ~한 후에 | 순서 (나중) |
| **because** | ~이기 때문에 | 이유 |
| **since** | ~이후로 / ~이기 때문에 | 시간 또는 이유 |
| **although** | ~에도 불구하고 | 양보 |
| **even though** | ~에도 불구하고 (강조) | 강한 양보 |
| **so that** | ~하기 위해 | 목적 |
| **as long as** | ~하는 한 | 조건 지속 |

**어순 규칙:**

종속절은 **앞에도, 뒤에도** 올 수 있다:

```
종속절 앞: If the documents are ready, I submit them.  (콤마 필요)
종속절 뒤: I submit them if the documents are ready.   (콤마 불필요)
```

종속절이 앞에 오면 **콤마**로 구분한다. 뒤에 오면 콤마 없이 쓴다.

#### 3. EXPAND — 짧은 문장에서 복잡한 문장으로

**if — 조건:**

```
Level 1: If it's wrong, fix it.
Level 2: If the client sends the documents late, the filing will be delayed.
Level 3: If the tax return contains errors, correct them immediately
         and notify the client.
Level 4: If the annual income exceeds 80 million won and the client
         has overseas assets, additional reporting is required.
```

**unless — 부정 조건 (if not):**

```
Unless you check it, don't submit it.
(확인하지 않으면 제출하지 마라.)

The meeting happens every Monday unless there is a public holiday.
(공휴일이 아닌 한 회의는 매주 월요일에 진행된다.)

Don't finalize the report unless the manager has approved it.
(매니저가 승인하지 않으면 보고서를 확정하지 마라.)
```

**when — 시점/이벤트:**

```
When the client arrives, offer them a drink.
(고객이 도착하면 음료를 제공하라.)

When the fiscal year ends, all accounts must be reconciled.
(회계연도가 끝나면 모든 계정을 정산해야 한다.)

Notify the team when the report is complete.
(보고서가 완료되면 팀에 알려라.)
```

**because — 이유:**

```
We chose this method because it is more efficient.
(더 효율적이기 때문에 이 방법을 선택했다.)

Because the deadline was approaching, we worked overtime.
(마감이 다가왔기 때문에 야근을 했다.)

The application was rejected because the supporting documents
were incomplete.
(증빙 서류가 불완전했기 때문에 신청이 거부되었다.)
```

**although / even though — 양보 (예상 반전):**

```
Although the preparation was thorough, we still found mistakes.
(준비가 철저했는데도 여전히 실수를 발견했다.)

Even though we doubled the staff, the workload didn't decrease.
(직원을 두 배로 늘렸는데도 업무량이 줄어들지 않았다.)

The project remained on schedule although the budget was cut significantly.
(예산이 대폭 삭감되었지만 프로젝트는 일정대로 진행되었다.)
```

**before / after — 순서:**

```
Before you submit the form, make sure all fields are filled in.
(양식을 제출하기 전에 모든 항목이 작성되었는지 확인하라.)

After the review is complete, send the final version to the client.
(검토가 완료된 후 최종본을 고객에게 보내라.)

Check the numbers before signing the contract.
(계약서에 서명하기 전에 숫자를 확인하라.)
```

**while — 동시성:**

```
While the auditor reviews the books, don't make any changes to the records.
(감사관이 장부를 검토하는 동안 기록을 변경하지 마라.)

While the sales team works on new clients, the accounting team will
process the invoices.
(영업팀이 신규 고객 작업을 하는 동안, 회계팀이 청구서를 처리할 것이다.)
```

**so that — 목적:**

```
We organized the files so that anyone can find them easily.
(누구나 쉽게 찾을 수 있도록 파일을 정리했다.)

Keep detailed records so that we can prepare for the audit.
(감사에 대비할 수 있도록 상세한 기록을 유지하라.)
```

### Lesson 23 — that절: 문장 안에 문장 넣기

#### 1. WHY — 문장을 명사처럼 쓰는 기술

지금까지 배운 접속사들은 두 절을 **나란히 또는 종속적으로** 연결했다. 하지만 `that절`은 전혀 다른 일을 한다: **문장 자체를 명사로 바꿔서** 다른 문장 안에 집어넣는다.

```
사실: The report needs revision.
     (보고서가 수정이 필요하다.)

내 생각: I think [사실].
        (나는 [사실]이라고 생각한다.)

합체: I think that the report needs revision.
     (나는 보고서가 수정이 필요하다고 생각한다.)
```

`that`은 여기서 **"~라는 것"**이라는 의미로, 뒤따르는 문장 전체를 하나의 **명사 덩어리**로 만든다.

왜 이것이 필요한가? 우리가 전달하는 정보는 크게 두 가지다:

1. **사실/정보 자체**: "The meeting was cancelled."
2. **그 사실에 대한 태도/판단**: "I believe / I know / I think / I doubt..."

That절은 이 두 가지를 **하나의 문장에 담는** 도구다.

#### 2. CORE — 핵심 개념을 가장 짧은 문장으로 체득

**that절의 기본 구조:**

```
주어 + 동사 + that + [완전한 문장]
```

**that절을 취하는 대표 동사들:**

| 동사 | 의미 | 예문 |
|------|------|------|
| think | 생각하다 | I think that it works. |
| believe | 믿다 | I believe that the answer is correct. |
| know | 알다 | I know that the deadline is Friday. |
| say | 말하다 | He said that the project was approved. |
| hope | 바라다 | I hope that everything goes well. |
| expect | 기대하다 | We expect that sales will increase. |
| assume | 가정하다 | I assume that the data is accurate. |
| doubt | 의심하다 | I doubt that this will work. |
| notice | 알아차리다 | I noticed that the file was missing. |
| suggest | 제안하다 | I suggest that we review it again. |
| confirm | 확인하다 | He confirmed that the issue was resolved. |

**that 생략 규칙:**

구어체/비격식에서는 `that`을 **생략**할 수 있다:

```
I think (that) the report needs revision.
I know (that) the deadline is Friday.
He said (that) the project was approved.
```

하지만 **생략하면 안 되는 경우**:

1. that절이 **주어**일 때:
   ```
   That he passed the exam surprised everyone. (O)
   He passed the exam surprised everyone.      (X) ← 문장 구조 깨짐
   ```

2. **두 개의 that절**이 나열될 때:
   ```
   He said that the error was found and that the correction was made. (O)
   He said the error was found and the correction was made.           (?) ← 모호함
   ```

#### 3. EXPAND — 짧은 문장에서 복잡한 문장으로

**Step 1: 기본 — 생각/의견 표현**

```
I think that we need more time.
I believe that this approach is better.
I know that the deadline is the main concern.
```

**Step 2: 보고/전달 — 간접화법**

```
The manager said that the deadline was moved to next Friday.
The client reported that the invoice was incorrect.
The team leader announced that we would adopt a new process.
```

**Step 3: 감정/반응**

```
I'm glad that the project was successful.
I'm surprised that the error went unnoticed for so long.
I'm concerned that the expenses keep increasing.
```

**Step 4: It + be + 형용사 + that절 (가주어 구문)**

```
It is important that all documents are submitted before the deadline.
(마감일 전에 모든 서류가 제출되는 것이 중요하다.)

It is clear that the current process needs improvement.
(현재 절차가 개선이 필요한 것은 분명하다.)

It is unlikely that the error will affect the final result.
(그 오류가 최종 결과에 영향을 미칠 가능성은 낮다.)

It is essential that the records be kept for at least five years.
(기록이 최소 5년간 보관되는 것이 필수적이다.)
```

주의: `It is essential/important/necessary that...` 구문에서 that절의 동사는 **원형(subjunctive)**을 쓴다:
```
It is essential that the data be verified. (O) ← 원형
It is essential that the data is verified. (?) ← 구어체에서는 가능
```

**Step 5: that절이 주어인 경우**

```
That the office closed early is unusual.
(사무실이 일찍 닫힌 것은 이례적이다.)
→ 이런 형태는 무거우므로, 보통 가주어 It으로 바꾼다:
→ It is unusual that the office closed early.

That he finished the entire project in one week impressed the team.
→ It impressed the team that he finished the entire project in one week.
```

**Step 6: 다중 that절 — 복잡한 보고**

```
The investigation revealed that the original calculation was wrong,
that the error had gone undetected for three months, and that
the responsible staff member was unaware of the updated guidelines.
(조사 결과, 원래 계산이 틀렸고, 그 오류가 3개월간 발견되지 않았으며,
담당 직원이 업데이트된 지침을 몰랐다는 것이 밝혀졌다.)
```

**Step 7: that절 + 조동사/시제 변환**

```
I knew that the plan would fail without proper preparation.
(나는 적절한 준비 없이는 계획이 실패할 것을 알고 있었다.)

She hoped that the revision would resolve all the issues.
(그녀는 수정이 모든 문제를 해결하기를 바랐다.)

We didn't realize that the mistake had been in the report for two weeks.
(우리는 그 실수가 2주간 보고서에 있었다는 것을 깨닫지 못했다.)
```

**세무 도메인:**

**일반 비즈니스 도메인:**


## Phase 3 총정리

### 배운 도구들 한눈에 보기

| 문법 도구 | 기능 | 핵심 역할 |
|-----------|------|-----------|
| 조동사 (can, must, should...) | 동사에 의미 추가 | 능력, 의무, 가능성, 허가 등 화자의 태도 표현 |
| 조동사 과거형 (could, would) | 거리감 표현 | 공손함, 불확실, 가정 상황 표현 |
| 관계대명사 (who, which, that) | 두 문장 합치기 | 반복을 줄이고 명사를 뒤에서 수식 |
| 관계부사 (where, when, why) | 장소/시간/이유 연결 | 부사적 맥락 정보를 자연스럽게 연결 |
| 제한적/계속적 용법 | 필수 정보 vs 부가 정보 | 콤마로 정보의 중요도 구분 |
| 등위접속사 (and, or, but) | 대등한 절 연결 | 나열, 선택, 대조 표현 |
| 종속접속사 (if, when, because) | 종속 관계 표현 | 조건, 시점, 이유, 양보 표현 |
| that절 | 문장을 명사화 | 생각, 의견, 보고를 하나의 문장에 담기 |

### Phase 3 자가 진단 체크리스트

```
[ ] 조동사로 능력/의무/가능성을 구분해서 표현할 수 있다.
[ ] could/would가 "과거"뿐 아니라 "공손/불확실"을 뜻한다는 것을 안다.
[ ] 관계대명사로 두 문장을 하나로 합칠 수 있다.
[ ] 관계대명사와 관계부사의 차이를 설명할 수 있다.
[ ] 콤마 유무(제한적/계속적)에 따른 의미 차이를 안다.
[ ] 등위접속사로 대등한 절을 연결할 수 있다.
[ ] 종속접속사로 조건/이유/양보를 표현할 수 있다.
[ ] that절로 문장을 명사화하여 다른 문장에 넣을 수 있다.
```
